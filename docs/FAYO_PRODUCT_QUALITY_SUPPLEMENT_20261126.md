## 已实现的合同

`V6_BO/src/core/product-quality-evaluation.js` 固定七维30项定义。每次评价绑定精确40位源码版本、统计环境、对象范围、窗口和预登记计划。每条观测必须匹配版本、窗口、范围、单位、计划版本及整个计划的 SHA-256 指纹；只改同名计划的阈值也不能复用旧通过结果。

比例数据分别记录分子、全量分母、已取得样本和缺失量；分布数据保留全量应取得数量及 min/max/mean/p50/p95/p99。未取得的样本不填零、不从分母消失。没有证据、窗口未结束、样本不足、旧版本、错误单位或计划不匹配都保持未知；不适用须事前说明理由及复核人，并留在30项分母。

五项关键安全指标固定要求正确率1且不能标成不适用：越权拒绝、旧价拒绝、成交幂等、账本对账及历史时点隔离。已取得的当前版本安全失败，即使计划缺失/修改、窗口未结束或还有缺样本，也阻止进入独立评审。其他高分不能抵消。通过状态仅表示显式输入达到所登记标准，仍需要独立回读证据。

收益、回撤及相对基线改善要求扣除费用和滑点的相同执行条件；误报/漏报要求完整事件复核范围；Brier损失要求独立校准评价样本。输入中的声明和证据哈希不等于真实性认证：输出明确标记预登记与证据尚未经独立认证。完整指标口径见[七维30项定义](SEVEN_DIMENSION_QUALITY_DEFINITIONS_20261126.md)。

输出没有综合分或预测概率，也不授予交易、发布或模型晋级权限。默认报告为30项未知、实际评价覆盖0/30；这表示缺少符合合同的真实输入，不表示产品质量为零，也不否认现有隔离测试。

## 只读命令与退出语义

在仓库根目录执行：

```bash
npm run quality:audit
npm run quality:audit -- --input /absolute/path/quality-evidence.json
npm run test:critical-mutations
```

`quality:audit` 无参数只读取当前 Git SHA，生成明确未提供评价输入的报告；不会主动读取账户、私密卷、行情或通知。输入文件必须是显式给定、不经符号链接、不超过1MiB的普通JSON文件。FIFO、设备文件、读取期间变大的超限文件会被拒绝，解析错误不会回显输入内容。

质量命令退出0仅表示完成一次证据审查，**不能用作全健康、验收通过或发布许可**。必须检查报告：`criticalReview.state=unverified` 表示仍缺安全证据；`blocked` 时退出2；非法输入退出1。所有关键条件达到标准时也只是 `eligible-for-independent-review`，最终批准沿用原流程。该CLI尚未接入在线健康页或HTTP接口。

## 固定四项变异的实际验收范围

`V6_BO/scripts/check-critical-mutations.js` 只在隔离子进程的模块编译阶段替换固定片段，仓库源码文件保持不变。子进程只获得最小环境，使用临时账户和本机回环测试；没有生产凭据、真实账户或外部通知路径。每次执行有20秒上限，基线加四项变异，未覆盖的故障组合不扩张成完成声明。

| 固定错误变更 | 使用的既有业务断言 | 本轮结果 |
| --- | --- | --- |
| 自动成交15秒旧价门禁放宽到180秒 | `automatic-paper-commit-quote-time.test.js`，检查锁内及落盘前拦截、现金持仓不变 | 已捕获 |
| 绕过本机只读纸面账户HTTP Bearer校验 | `paper-service-http.test.js`，未经授权不得读取原账户 | 已捕获；不代表全部服务入口已覆盖 |
| 取消重复成交事件ID检查 | `paper-account-ledger.test.js`，相同事件不能重复扣款或增加持仓 | 已捕获 |
| 买入现金多保留1元 | `paper-account-ledger.test.js`，数量、费用和现金精确勾稽 | 已捕获 |

变异分类要求完整且一致的平面TAP报告、确实执行了测试、原基线通过，以及变异测试中实际的业务断言失败。空报告、全跳过、缺结束计划、虚假汇总、语法错误、加载错误和超时均为无法评价。存活变异也不能自动标成等价。该次4/4只证明上述四种错误被识别，不能换算成整个系统的安全率。
