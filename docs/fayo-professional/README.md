## 三、数据、模型及交易边界

1. 优先官方公告、公开文件、许可允许的网页、自主采集及本地数据库。登记每个现有金融接口的提供者、实际独立上游、使用条款、限流、费用、允许用途、频率、覆盖、来源时钟和降级。可评估合法替代，替换前验证同口径兼容及回退。
2. 新第三方金融或服务接口默认关闭，启用须用户明确授权。生产业务使用本地程序、统计方法及合法本地模型。禁止依赖ChatGPT、OpenAI、DeepSeek云端、Claude、Gemini等外部模型或第三方中转。内部前后端API继续使用。不采购、不开通额外权限，不绕验证码、登录、反爬或数据许可。
3. GitHub限开发、版本管理及可选更新用途。核心静态资源随包提供，查字体、脚本、图标、CSS、图表、遥测、SDK及启动阶段隐性下载。模型权重、依赖、运行时按许可准备离线安装及恢复材料；记录版本、包清单、哈希、来源、兼容平台及校验结果。
4. 跨境源不可用时，仅使用用途合格的合法备源，或显示不可用及原因。保留上一有效数据的原日期、原价和来源。日线与延时报价不可用于模拟成交。执行继续受原15秒报价、证券资格、T+1、现金与持仓守恒、独立风险和人工审批约束。
5. 软件升级使用原发布者、完整安装包、版本与完整性校验。回退只回代码与兼容配置，先做停写冷备，保留新账户流水、研究历史与版本关系。桌面、手机读取同一后台账户和业务状态。
6. 验收须区分无境外服务时的核心启动、本地研究回测与风险保护，及需要在线数据的实时行情、新闻、跨市场研究。逐项保留域名阻断规则、拒绝日志、冷启动记录、受影响消费者及失败路径。模拟阻断、真实大陆线路、浏览器视口与真机分别签收。

## 四、策略及研究取舍

趋势、行业动量、反转、专业短线、事件、基本面、防御及现金进入同一竞技机制。先登记证券范围、目标、持有与退出期限、频率、费用、风险预算、比较基准和标签成熟条件。原十四条、八字口诀、GPT五策略、Python三轮以及其他研究条件均可修改、合并、替换或停用。正式风险与账户权限沿原审批。

|问题|首个对照|条件性挑战者与采用依据|
|---|---|---|
|市场突变、市场状态|同时段经验分布、原趋势与广度|稳健Z、EWMA、CUSUM、HMM或变点模型；同一误报预算下衡量发现延迟、漏报及计算开销|
|选股与二阶段机会|相对强度、等权或线性多因子、简单成交及净价值过滤|Elastic Net、树模型、学习排序或Meta-labeling；按期限比较Top-K净收益、容量、尾损及覆盖|
|文本与产业传导|原文、时间、实体、主营与订单证据|规则与合法本地文本模型对照；否认、撤回、文本注入及纯概念作负例|
|收益区间与概率|历史经验分位数、前值、简单残差|分位数、校准与共形研究；Kronos、Chronos、TimesFM等须单独核权重许可、训练污染、覆盖和资源成本|
|自动因子与组合|固定权重、预注册消融、简单风险预算与现金|受限自动特征、专家组合、稳健优化；预设预算、隔离执行、独立留出及原审批|
|可靠性与实际价值|同样本费用后成绩、回撤、误报、时间节约|交易日区块重采样、DSR等须满足统计前提。行为点击只评价体验|

研究单条件、成组、阈值敏感性、连续与硬切分及交互。训练、参数搜索、验证、留出、前向影子和模拟成交分别记录；防未来数据、重叠标签、幸存者偏差及事后挑期限。既报共同样本又报各自全覆盖，保留缺价、无信号、误拒、弃权、未成交和部分成交。批准优秀策略进入具体选股、排序或研究推送，退役版本保留历史重放。

## 五、统一产品工作区与使用路径

|建议工作区|用户实际操作与下游|
|---|---|
|01 决策首页|按交易时段看市场变化、适用策略、机会、风险与数据缺口，跳到证据或选择观察现金|
|02 行情中心|指数、收益分布与广度同窗比较，切换合法可用周期|
|03 政策与事件|查原文、变更与反面证据，联查公司、板块、持仓|
|04 ETF及大资金|分列成交、份额、申赎、正式披露及未知主体|
|05 板块与主线|热力、梯队、扩散与集中度对比，核实产业链和持续时间|
|06 选股与机会|按期限、市场和策略过滤，查看原信号、当前报价及失效条件|
|07 个股研究|行情、新闻、推送、持仓及复盘共用同一证券详情；下钻量价、基本面、证据与风险|
|08 策略竞争|比较研究、影子、批准及停用版本，追到审批、实际消费及回退|
|09 模型与因子|核版本、用途、适用域、贡献、样本外误差及漂移|
|10 历史回测|查冻结范围、成本、退出路径、不确定性与不可成交记录|
|11 资产持仓|对照原持仓、新候选与现金，查看冻结资金和真实风险敞口|
|12 模拟交易|从权威账户追委托、部分成交、撤单、费用及完整流水|
|13 独立风险|查触发依据、持续或升级状态与解除条件，风险提醒可追到原账户|
|14 资讯及推送|按优先级与权限接收，区分网关、送达和已读，打开后复核|
|15 复盘与进化|追踪发现延迟、判断、时机、执行与误拒，把重复失误送入预注册|
|16 金融数据|按用途看源身份、授权、健康、原时点、主备与受影响业务|
|17 系统与安全|设备、角色、会话、撤权、更新、日志与备份恢复|

视觉与导航由设计者决定。电脑侧重多栏、键盘、联动图表、大表和比较；手机先给结论、条件和风险，可展开全部高级能力。全局股票和功能搜索、自选收藏、常用入口及返回状态均要联测。图表按真实周期、单位、来源和时间绘制，支持触控、缩放、十字光标及横屏；缺周期或成交时保留缺口。强度、机会、预测可靠性、风险及成交资格各自展示。

## 六、实施顺序和签收

1. 固定基线、相关候选、已有任务映射、数据权限和现场边界。
2. 贯通消息与盘面双向触发、证据分级、广度及新旧主线。
3. 策略及条件登记、公平竞争、简单基线和独立样本外研究。
4. 接入二阶段价值、机会时效、持仓与现金比较及独立风控。
5. 以原通知、账户与终端验证实际消费，建立前向、回退和持续监测。高阶能力按合法数据和实证增益推进。
6. 总管统一集成后冻结业务覆盖矩阵。先审主要页面设计稿；确认后开展最终UI/UX。完成历史功能及新能力双端映射、真实浏览器、真机、断网与大陆现场验收。
7. 出具分别对应精确代码版本的专项、全量、消费和现场报告。5/20/60交易日为观察节点；稀有事件或标签未成熟继续积累。

单项状态分别记录设计决定、工程实现、运行证据、实际消费、价值结论、用途授权与现场状态。验收包应含源及授权、原始/接收/决策时点、输入指纹、成本与预算、策略/模型/账户版本、输出及有效期、消费者、拒绝理由、成熟结果、命令与日志、阻塞、恢复与审批责任。模拟交易与实盘授权独立。完整验收由原总管签收。
