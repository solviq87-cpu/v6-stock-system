## 后复权供给

默认私有路径是 `SHORTLINE_ROOT/center-history/`。只读查询不会为不存在的证据建立档案。收盘调度在北京时间 16:00 后从已有真实候选中取最多三只，日内最多三次尝试；进程锁、持久尝试记录和源访问策略在重启后仍有效。网络等待后、落盘前复核主实例身份。没有安装或启用新的收费来源。

当前两种历史适配器只覆盖沪深股票。调度先筛选支持的市场再取前三，北交所等未覆盖代码在状态中明确列出，不能让一只未覆盖股票拖垮整批沪深采集，也不把它们计为已经覆盖。

新采集器检查原请求与返回旗标：东财 `fqt=2`，BaoStock `frequency=d / adjustflag=1`。保留原始响应、SHA-256、请求范围、单位、实际抓取时间和缺项。旧 qfq / 不复权采集器保持原样，不把旧数据重新贴为 hfq。

同源同日的相同数据保留首次可知时间；后续修订不覆盖历史，冲突键进入隔离。过去时点回读不受后来修订影响。附属历史库损坏时 GET 明确显示缺口，反馈 POST 拒绝写入提案。中心仍要求独立来源、统一口径、原时点及因果顺序，容忍阈值没有放宽。

本环境对 600000 / 2026-11-24 实际执行过一次独立只读采集：东财未返回成功 HTTP；BaoStock SDK 未安装；所得行情行数为 0。首次回执未保存 HTTP 数字状态，因此不猜测状态码。两家公开日线格式也没有逐日源端时刻。供给链已接入不代表已有可用于 IC 或 Walk-Forward 的真实样本，缺项会在两端展示。

字段依据：[BaoStock 日线](https://baostock.com/mainContent?file=DailyUpdates.md)、[复权方法](https://baostock.com/mainContent?file=factorInfo.md)、[东财行情页](https://quote.eastmoney.com/sh600000.html)。适配器依据本轮读取的真实供应商格式；接口变化仍须由原校验拒绝不兼容返回。

## 冻结计划观察与评分

默认私有路径是 `SHORTLINE_ROOT/plan-observations/`，与账户账本分开。观察器只能读取，不能调用买入、卖出、账户保存或外部通知。服务层单独把首次已持久记录的触发交给原私密推送函数，继续受主实例、额度、静默及投递队列约束。

原市场时钟的八位日期在服务边界转换为统一交易日期，观察、持久化与原预检使用同一次异步读取完成后的时点。每轮仅检查当日计划及当前持仓中仍能通过原买入事件关联的历史计划，旧档案完整保留。

每条证据绑定计划字段指纹、股票、日期、原报价来源及时间、接收时间、观察时间、原买入事件和剩余数量。追加批次有哈希链、私有权限、进程锁和原子索引；读回核验全链。未配置 webhook 时保持「未配置」，不会把“观察到”当作“已送达”；配置恢复后不重放旧触发。

真实持仓的止损/目标触发沿用原「持仓风控」分类；进入买入区间的观察沿用普通提醒额度（当前「其它」上限为每日一条），不会绕过原配额。入队和每次出队均检查中心启用、主实例、私密配置、连续竞价、同日及原报价 15 秒时效。调用方复核与原新闻复核串联，原新闻拒绝不能被新回调覆盖。过期或已关闭的观察不会在排队重试后继续外发；触发记录仍然保留，送达以原通道流水为准。

买入窗口复用 `executeDecisionPlan` 的原门禁，买入回调只作为只读检查边界，不会成交。原等权预算、申报单位、费用、监控容量、封板和量参与率继续收紧。启用自定义统一风控或存在待成交委托时，缺少完整事务预检就保持未知，不能只凭报价给出允许结论。

退出窗口核对原账户启用状态、原跌停巡检、同一持仓批次、T+1、冻结卖单、整手、费用和原 1% 量参与率。部分卖出逐笔扣减；清仓后同代码的新买卖不归到旧计划；重叠批次归属不清时停止归责。

评分在收盘后形成，观察口径是 **5 秒巡检、最大 15 秒采样间隔**。这证明的是采样覆盖和原模拟约束，不证明两次采样之间的走势或真实盘口成交。断线、停机、时点倒序、源端报价不推进均不能填成完整覆盖。连续可用的两次原始报价与原成交相互核对；当日开仓止损仍受 T+1 限制。原 ATR / 移动止损及自动退出规则没有被计划价替换。

## 同一反馈提案进入原验证

新增 `POST /api/decision-center/feedback` 只接受 `day`、`revision`、`proposalFingerprint`。浏览器不能上传 weights、目录、时钟或权限标志；普通研究入口不能冒充中心的内部授权。

worker 与研究 GET 共用 `composeCenterHistory`。在原档案锁内重读 revision，再复算提案，核对获批基线、词典、实际因子/价格/标签、成熟成交、冻结计划及原交易日历证据。即使日期集合相同，日历来源或可知时间变化也会使旧指纹失效。

中心只修改获批基线中已存在的同名因子，变化幅度仍受 8% 上限约束。原训练、时间外、样本外、成本压力及风险五关共用原实现；原普通候选的算法、阈值与人工审批不变。采用中心原训练/验证/测试窗口及 purge，已经使用的留出期不得再用，训练标签或获批基线晚于首个留出日时拒绝。

实际持久化前，worker 持原档案锁向主线程重新请求授权。编辑身份或主实例角色已变化、授权握手失败或超时，均不得提交候选。两设备并发时原 revision 冲突继续返回 409。成功提交只代表原验证结果已保存，不会自动批准或替换生产权重。界面直达 `lab/shortline-versions` 查看验证与审批。

Q 回流只使用已经核实的源异常与一致性证据。组件值、固定权重和证据指纹可追溯；策略亏损不等于行情质量差，缺实时证据时整体 Q 继续为空。
