## 四维合同

新增字段由 `V6_BO/src/core/risk-state-contract.js` 派生，合同版本 `fayo-risk-state-20261126-v1`。原 `severity`、`evidenceStatus`、`executionStatus`、协议 `fayo-risk-workbench-v1` 和原执行接口保持兼容；客户端不能把新展示字段作为下单许可。

| 字段 | 含义与边界 |
| --- | --- |
| `assessmentState` | `risk-detected`、`not-triggered`、`unable-to-assess`；首次缺数不会默认一级，未命中不等于安全 |
| `riskLevel` | 1–4 或 `null`；仅命中且有可评价事实时给出等级 |
| `evidenceState` | `complete`、`partial`、`conflict`、`unverified`；真实错误记录可以完整，但行情仍断流 |
| `dataState` | `valid`、`stale`、`missing`、`interrupted`；原报价过期不被接收时间刷新 |
| `actionState` / `actionReasons` | `allowed`、`blocked`、`unconfirmed` 与原核验原因；最终提交仍在原权威后端重检 |
| `riskContract` | 合同/规则/输入版本、配置状态、首次可知与原始时间、缺项、适用范围；`canAuthorize:false`、`probability:null`、`predictiveValue:unverified` |

一级只表示已经出现的可追溯观察。旧研究 warning/critical 在没有独立证据、已登记观察窗口或生效规则证明时，不包装成二/三级，旧紧急提示仍显示并沿原发送逻辑处理。二级要求上游已经登记并验证的窗口：独立维度必须同时拥有不同的维度、根因和证据引用；持续增强则需要达到登记数量的独立、按时点排序观察。当前只是接收这些证明的合同，没有宣称已产生合格的真实二级候选。

三级只引用原启用规则的实际超限结果。四级只映射已实际捕获的原账户/关键报价读取故障，影响范围是账户或数据链；它不表示个股正在下跌，也不添加自动清仓能力。配置已生效与预测有效分别记录。

## 时间、状态与恢复

- `generatedAt` 是报告生成时间；`sourceAt` 与 `dataAt` 保留原证据/逐票时点；未取得 `firstKnowableAt` 或输入版本时直接列缺项。刷新、重启和 receivedAt 不补造原始时间。
- 已保存的 `lastValidRisk` 只取完整证据且数据有效的实际风险；真实系统错误的四级记录允许行情缺失/断流。缺数、源错误、观察行消失或已读都不能清除该记录。原模块本次未返回的未解除根因仍进入统一 `risks`，以未知状态保留原 ID 和时点，并按上次有效等级排在首页优先位置。
- 解除必须具有晚于最后有效风险的全新有效 `sourceAt`。原账户事故需要对应对账回执；原报价链事故需要原链恢复和有效原报价；原规则需要同版本重新核验已不超限。换规则、仅报价恢复或旧意图恢复均不能代替相应条件。
- 降级同样需要新有效证据及相应恢复条件；不能用普通研究行覆盖未解除的硬规则事故。降级保存在兼容的 `group.levelChanges`，不扩展原通知事件枚举；未知间隔仍记录自上次有效等级的变化。所有已核验降级后的真实复升都记录新升级，不被历史最高等级吞掉；二级仍沿原普通冷却，三级/四级及时通知。严重升级不等待普通冷却，原硬风控仍在原提交路径立即裁决。
- 旧持久行在其原记录时点转换成派生视图，GET 不改写文件、事件或历史证据。原事件 ID、账户期间、预留和唯一写者继续有效。

## 发送与双端

调用链仍为原 runtime → 同一生命周期持久预留 → 原 `sendPrivate`/`pushAll` 队列。发送前的报价读取异常只能为“这次读取异常本身”提供事实证明；复核原账户期间、角色、通道和原故障仍存在后才可排队，不授予持仓风险配额豁免。读取已恢复时，旧故障消息停止外发。未配置、排队、网关受理和接收端确认继续分开；没有真实接收回执不显示送达。

电脑 `/`、手机 `/m`、首页摘要、个股与风险页消费同一个后台事件/合同；未知显示本次原数据时间和原因，并保留未解除的最后有效等级。原粉紫样式、设备权限和账户读写路径未另造分支。应用版本保留父 PR 的 `20261126aa`，本补丁前端修订 `risk-state-20261126-1`、缓存后缀 `risk-state-1`；总管与最终交付聊天在最终整合时统一正式版本。

## 已知限制与完成口径

1. 原账户完全不可读时可展示四级错误事实，但不能证明 accountEpoch，现有持久提醒/发送链因此拒绝新账户期写入。此时没有伪造期间或创建第二份事故账本，仍需原账户恢复与对账；不能声称该场景已完成持久外发闭环。
2. 原通知日限额/普通冷却仍保留。日限额和普通冷却原因以同一生命周期中的有界字段持久展示，不增加发送或重试；跨账户统一故障影响清单和真实通道回执仍需原通知负责人集成验收。
3. 原始公告、修订与 K 线时点证据由现有上游负责；本补丁不把候选识别、双端显示或规则正确性当作预测价值证明。
4. 本地测试使用隔离数据/临时权威模拟账户；生产行情、真实通知、现场数据备份恢复、5/20/60 个交易日窗口均未完成。

专项、完整回归、完整服务隔离启动及两类浏览器检查分别记录在 [验证页](validation/fayo-risk-state-20261126/README.md)。待总管与最终交付聊天对最终合并 SHA 重新核验，才能登记已部署或真实运行状态。
