## 不可妥协的功能约束
1. UI 必须使用 V6 现有真实接口/数据模型，禁止把示例股价、评分、策略收益或风险数据伪装成实时结果。
2. 数据缺失时显示“暂无数据 / 未认证 / 数据时间”，不制造假数据；模拟数据必须显式标注。
3. 不破坏 V6_BO 原有四套策略、历史回测、观察池、模拟交易、风控、时间戳/来源审计。
4. 手机端和电脑端独立按各自参考图校准；响应式变化不能成为删模块的理由。
5. 保留无障碍、触控可用性及异常/加载/空状态；不因视觉还原取消安全门禁。

## 验收方法
1. 固定与参考图一致的 viewport、设备像素比、字体、测试数据状态，逐区域截图比对。
2. 核查结构、尺寸、间距、颜色、字重、阴影、图表与图标；有偏差继续修改。
3. 使用自动截图差异工具和人工核查；任何容差须有明确理由并获用户认可，不能自行宣布“足够相似”。
4. 运行 `cd V6_WEB && npm ci && npm run build && npm test`，以及受影响的 V6_BO 测试。
5. 未达到参考图一致性之前不得称“1:1 已完成”；测试未运行不得称“已通过”。

## 实施顺序
- 第一阶段：固化参考图与设计 token、布局和双端路由；先做结构/视觉。
- 第二阶段：逐卡绑定现有 V6_BO 数据源，补数据状态、解释和风险门禁。
- 第三阶段：双端截图回归、交互回归、全量测试与验收。
