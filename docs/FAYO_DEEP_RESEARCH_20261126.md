## 接口、权限与持久化

| 接口 | 行为 |
| --- | --- |
| `GET /api/research/deep` | 原主研究档案、原新闻证据、原短线档案及原账户只读聚合；不创建对照、不写账、不发送通知 |
| `POST /api/research/deep/evidence` | 编辑者明确导入结构化来源材料，1—100 条/次、512 KiB 上限，稳定请求 ID 和档案 revision；不发起外部采集 |
| `POST /api/research/deep/alternatives` | 2—5 个事前方案封存；账户、时钟、手续费及原生效约束由服务器取得；客户端只声明周期和备选 |
| `GET /api/research/deep/acceptance` | 安装校验、服务器实际观察记录与 78 项六维状态；不接受回填“运行天数” |
| 原 `GET /api/research/risk-center` | 增量 `deepResearch` 字段，复用原风险页；原字段与业务含义保留 |

全部新接口沿原编辑者身份、设备权限、同源和主副角色。仅原主实例允许写；排队前、锁内提交时、响应前复核授权。私有结果 `Cache-Control: private, no-store`。客户端不能指定档案路径、账户文件、服务器时间或测试模式。研究 worker 仍使用现有任务队列、内存限制和 55 秒上限，计算不阻塞行情主线程。

证据与对照沿原 `V6_RESEARCH_WORKSPACE_DIR`（默认 `V6_BO/data/research-workspace`）保存。78 使用原短线私有根下 `runtime-acceptance`，只保存运行观察，不存第二套持仓/现金。文件导入先预览、明确保存，敏感字段、私密 webhook、Basic/Bearer 值及原型污染键被拒绝。导入首次获知时点是服务器实际收到时间；声明的历史时间另存，不能变成当时系统已知。

结构化导入形状为 `{type, records}`；HTTP 提交另带当前 `revision` 与稳定 `requestId`。支持 `events/eventOutcomes/expectations/actuals/relations/depth/themes/portfolio`。证据有稳定 `id`、来源、来源地址或证据引用、修订与公开时间；详细字段及缺失反例见对应核心测试。导入是来源声明，不自带外部真实性认证。持仓、报价、手续费、原风险策略和持仓数量上限不接受导入覆盖。参与率通过原服务只读 `executionLimits()` 取值，研究有效比例只能取更严值；研究平均成交额、历史前日股数容量与原实时累计成交股数是不同口径，不能互相冒充真实执行资格。

`displayed / queued / delivered / executionIntent / orderSubmitted / fillConfirmed` 分别保留，未取得回执就是未知。本次没有新通知发送。原强制风险处置也不会被“换仓不划算”的研究偏好阻止。目标权重、路径关联、扰动结果和假设成交均不能直接调用下单或修改正式权重。

原账户读侧还核对未终结订单：可卖量扣除原卖单冻结；存在买单冻结时不另算费用伪造可用现金。缺可用现金/开放订单约束时研究保持不调整或待验证。

## 实际运行计数规则

只有主实例、当前交易时段、原显式运行日历、完整安装版本核验和包含有效原价格/原始时点的真实报价满足条件的服务器样本才有资格计入。运行日历复用既有 `V6_TRADING_CALENDAR_FILE` 对象与其完整日期/来源/哈希；未配置时，研究日历只能产生被排除的观察，不能提升其 `runtimeEligible:false` 资格或按静态假日表推定未来全年覆盖。每分钟最多追加一次，按五分钟时段检查覆盖；完整一天至少覆盖 40/48 个区间、上午和下午各至少 20 个、并包含两场开头/结尾区间。这个覆盖规则是工程验收缺省，不是策略收益认证。

验收协议记录行情覆盖分母、采集成功率、风险/送达、原执行/对账、策略样本和结果、双端权限/版本及响应/资源指标。当前已接原行情、账户对账/模拟成交和进程资源；各组尚未合入的送达、成熟策略与客户端回执不猜填。行情证据保留有界原始时间抽样和全批输入摘要，便于复核15秒判定。没有可核实来源的值保留 `null`：已观察股票数不会冒充全市场覆盖分母，消息排队不会冒充送达，没有实际客户端回执不会宣称双端已一致。早期日历缺失、版本变化、失败采集、缺失交易日都保留。5/20/60 窗口达到后仍需逐项证据和问题复核；代码不会自动宣称长期验收通过。
