## 原生入口与可运行接口

桌面 `/`、移动 `/m` 共用 `#/lab/evolution`，从“回测 → 研究进化工作台”进入；首页按已保存优先顺序展示研究卡。需要原编辑者身份，不新增账户或授权体系。
以下源码路径均相对 `V6_BO/`：`src/core/intelligence-evolution.js` 汇总原短线档案及研究链；三个模块为 `evolution-market-evidence.js`、`evolution-research-statistics.js`、`evolution-workflow.js`，前端为 `public/nova/evolution-view.js`。

- `GET /api/research/evolution?symbol=600001&horizon=5`：返回 `market`、`similar`、`statistics`、`workflow`、来源及指纹。
- GET 仅允许 `symbol`、`asOf`、`horizon`、`export`，重复或额外字段拒绝；代码为六位，`asOf` 为不晚于当前时间的 13 位 Unix 毫秒，`horizon` 仅 `1/5/20/60`，`export` 仅 `0/1`。
- `export=1` 重新鉴权读取同一报告，前端下载 JSON；响应为 `private, no-store`。GET 不接受请求体，接口不接受用户提供的文件路径、行情或历史矩阵。

POST 同一路径，不带查询参数，JSON 请求体最多 64 KiB；`requestId` 为 8—100 位字母、数字、下划线或连字符。

```json
{"action":"preferences","requestId":"evolution_layout_0001","expectedRevision":0,"value":{"selectedCode":"600001","search":"","status":"all"}}
```

这是合法最小示例；实际保存先 GET，再将完整现有 `workflow.preferences.value` 修改后提交，避免遗漏原分组与布局。`expectedRevision` 必须等于当前版本；同 ID 同内容重用原回执，同 ID 异内容拒绝，陈旧版本返回冲突。
允许字段为 `groups/templates/columns/search/status/activeGroup/selectedCode/sectionOrder/homepagePriority/expanded/scrollTop/density`；最多 20 组、每组 200 只及 20 个模板，严格校验代码、引用分组与栏目白名单，首页风险信息保留。

```json
{"action":"diagnostics","requestId":"evolution_diagnostic_0001","symbol":"600001","horizon":"5"}
```

诊断只允许 `action/requestId/symbol/asOf/horizon`；可选 `asOf` 和 `horizon` 在 POST 中须为字符串。诊断从服务器原档读取输入，`horizon` 传入原持有策略的 `holdDays`。副本可读取，不能保存偏好或诊断。

## 原存储、权限与可重复诊断

沿用 `research-workspace-store.js` 的私有追加式 hash chain、原跨进程锁、原子写入及 0700/0600 权限；新增事件种类只有 `candidate-lifecycle` 和 `evolution-preferences`，诊断复用 `diagnostic`，没有第二套账户、行情 collector 或交易账本。
原 `saveScreen` 自动关联生命周期来源，读取投影也重放旧筛选全历史；浏览器不能提交候选系统状态。生命周期当前表保留全部已观察证券，历史明细及后续比较按所选代码显示，并注明范围。
授权覆盖三个边界：HTTP 入站原角色/同源校验；worker 排队后重新核验，并在原锁内真正落盘前再次核验；返回私人报告前再次校验。撤销编辑授权或切换副本后不写新事件；设备撤权后也不返回已读出的私人结果，合法副本仍可读取。
偏好使用 CAS；诊断先查 `requestId` 与命令摘要，重试返回原回执，不重复重计算。不同内容不能借旧请求 ID 覆盖历史。
诊断缓存同时绑定证券、原历史指纹、`nativeInputsFingerprint`、实现指纹及 `horizon`；旧结果仅在所选时点已经可知且全部版本匹配时复用。
`evolution-diagnostic-version.js` 逐文件绑定本地实现依赖、四体系、指标、账本、费用、风险、公司行为、参数包、依赖锁及 Node 版本；缺失、链接或越界不能生成可复用版本，不执行被扫描源码。
报告区分包含当前档案修订的 `fingerprint` 与可见证据的 `visibleEvidenceFingerprint`；诊断输入、命令和原事件 hash 均可追溯。历史截止回放不会用当前人工账本状态替换旧状态。
重诊断在既有 worker 中运行；单任务 55 秒、384 MiB 边界，诊断历史最多 20 只、每只 600 根、总计 6000 根。越界或证据不足明确报错/不可评估，不生成替代行情。

## 真实证据与统计解释边界

工作台合并 workspace 行情时，首次服务端 receipt 是 `knownAt` 下限，保留供应商原时点及原事件 hash；事后一次导入多年历史不会变成当年已知信号。相同回执去重，冲突身份隔离；后到的可选字段不附着到较早回执上，正式与教学样本分区。
分钟、日、周、月证据均检查取得时间、闭合时间、来源与价格口径；周月由日线推导时必须覆盖日历中全部应有交易日。不同周期不是独立胜率样本。
财务 16 项为 ROE、单季净利同比、单季营收同比、负债率、经营现金/净利润、应收同比、存货同比、毛利率、商誉/净资产、净利率、基本 EPS、每股经营现金、应收周转天数、存货周转天数、流动比率、速动比率。
每项附报告期、披露/修订、实际取得时间、单位及原始引用；没有证据保留 `null`，不得用零、累计口径或新修订替代旧单季事实。风险阈值是透明研究提示，未验证行业普适增益。
单笔收益以原分币结算成本复算；原模拟与人工申报已对账分源。模拟计划偏差须匹配成交前原冻结计划指纹及买入事件，人工记录核对原冻结建议和对账引用；事后同 ID 改计划不能改写历史纪律。
MFE/MAE 仅在日历内全部实际持有时段都有有效行情覆盖时给出；部分行情只列已观察极值或上下界。日 K 包含入场前/离场后价格、同根 K 线同时触及目标与止损时，不推断触发先后或可成交性。
策略竞争、融合、消融和收益分布保留失败、拒绝、未成熟及排除原因；不同版本、环境与来源分组，缺数不计失败或零收益。15 项扰动与 8 项融合均披露，不据此自动调权或晋级。
DSR 方法来源：[The Deflated Sharpe Ratio](https://www.davidhbailey.com/dhbpapers/deflated-sharpe.pdf)；PBO 方法来源：[The Probability of Backtest Overfitting](https://www.davidhbailey.com/dhbpapers/backtest-prob.pdf)。
DSR/PBO 须有完整试验历史、同期完整候选收益矩阵及非重叠区间；DSR 还需明确有效独立试验数。原 IC 汇总不能充作净收益矩阵，退化方差及缺数据返回不可评估；bootstrap 固定披露种子、区块与重复次数。
通过 `V6_FACTOR_AGENT_CONFIG_FILE` 指向已有 factor agent 配置，读取其原 `cycle.modelDir/captureDir` 和不可变试验档案；未配置不猜示例目录，不重置预算、不新建 collector。旧试验档案缺首次落盘时点时，仅作现存完整尝试的保守审查，不宣称历史已知。
AI 项目评估的是实际规则解释与安全合同，`modelInvoked:false`；它没有外部 LLM 质量分、真实成交权限或生产参数变更权限。所有模块维持研究标志，不写原账户、不交易、不发通知、不自动晋级。
