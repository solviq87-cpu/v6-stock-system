## 4. 本轮主补丁：现象、证据、原因与修复

### 原02／04／22／49：自动成交提交前原始报价15秒门禁

**现象与证据。** 在基线的原权威服务`saveLegacy`入口，隔离重现15001、60000和180000毫秒旧报价仍能提交新自动成交；180001毫秒才被拒绝。接收时间更新不能证明这些报价是新的。反例只在临时账户运行，没有修改真实账户。

**原因。** 上游15秒检查与权威提交处180秒历史合同不一致；等待账户锁或构造暂存成交也可能使检查后报价过期。

**最小修复。** [paper-application-service.js](../V6_BO/src/core/paper-application-service.js)仅在新增自动成交时核对原始`quoteAt/timestamp`、安全整数、未来时间、当前交易日及15秒边界，并在持锁逻辑与最终写入前复核。15秒整仍允许，15001毫秒拒绝；收到时间不替代原始时间。拒绝时保留原账户字节并留下原审计原因。

**验证入口。** [automatic-paper-commit-quote-time.test.js](../V6_BO/tests/automatic-paper-commit-quote-time.test.js)覆盖买卖两向、未来／缺失／冲突时间、跨日、锁等待、暂存处理超时、重启幂等，以及既有成交证据只读兼容。修后隔离复现15001／60000／180000毫秒全部拒绝，原现金与持仓不变。

**剩余。** 本地完整回归5027项为5026通过、0失败、1项PowerShell环境跳过；精确SHA CI和生产真实链路仍分别记录。已持久化历史证据不重写；显式导入／模拟的人工研究成交保留原历史合同，不混为当前自动成交。没有新增账户、交易权限或替代账本。

### 原05／30：私密观察提醒的事件身份、升级冷却与旧回执不确定性

**现象与证据。** 原摘要分别排序风险类别与事件ID，A高B低→A低B高时可形成同一fingerprint；即使摘要不同，只比较critical总数也会让新严重对象被普通冷却压住。旧聚合回执不能确认升级后当前对象身份，监控入口还会丢弃新增加的不确定性标志。

**原因。** 对象和严重程度没有绑定；旧格式没有逐事件严重身份；上层返回白名单没有同步状态合同。

**最小修复。** [private-risk-feishu-delivery.js](../V6_BO/src/core/private-risk-feishu-delivery.js)绑定事件ID、规则类别与等级计算摘要；仅新critical身份绕过普通冷却。普通变化仍冷却，每日限额保持可见。持久化不确定外发仍预留，不因重启或迁移重发。旧v1/v2聚合命中保留`legacyIdentityUnverified`；历史网关结果单列`previousGatewayAccepted`，不冒称当前对象`gatewayAccepted`。状态始终不等于设备送达。[private-risk-monitor.js](../V6_BO/scripts/private-risk-monitor.js)透传严格布尔的不确定标志，不透传私密ID。

**验证入口。** [private-risk-escalation-identity.test.js](../V6_BO/tests/private-risk-escalation-identity.test.js)、[private-risk-monitor-identity.test.js](../V6_BO/tests/private-risk-monitor-identity.test.js)，及原private-risk-feishu-delivery／private-risk-journal-monitor回归。覆盖等级互换、重排稳定、普通冷却、新严重对象、未知回报不重试、旧聚合迁移、重复ID拒绝、私密字段不外泄和监控投影。最终组合专项35/35及完整回归已纳入旧身份网关语义，不累计前后不同代码版本的数量。

**剩余与边界。** 当前实际调用链是手工持仓观察→本机private-risk-notify→原发送模块→private-risk-monitor；不是整个权威风险中心已经完成。#359整合后仍需验证其事件投影及原队列。测试均使用注入的HTTP替身，**没有发送真实消息**。新版状态上限1MiB；旧32KiB读取器可能拒读大记录，回滚必须保全新增去重记录并使用兼容读取器／向前修复，禁止删记录解锁后重发。

### 原20／50／55／57：必需浏览器门禁与工作流真实接线

**现象与证据。** 候选ruleset列有13项必需检查，却未包含真实浏览器`visual-geometry`；UI workflow使用路径过滤，直接把浏览器设为必需会让后端／文档PR没有对应结果而一直等待。新增专项脚本也可能只存在于目录，没有进入workflow。

**原因。** 文档、候选配置、触发范围与实际执行清单没有共同验收。

**最小修复。** [ruleset候选](../.github/rulesets/v6-dev-required-checks.json)加入`visual-geometry`，共14项；[UI workflow](../.github/workflows/v6-ui-browser.yml)去掉push／PR路径过滤，保留原分支范围，执行原真实浏览器套件。后端／文档提交因此增加CI开销，不使用空绿占位。[审计脚本](../V6_BO/scripts/audit-fayo-integration-gates.js)接入实际`npm run check`，检查状态到job、dev触发、脚本遗漏和吞错；带引号／alias等未支持布局拒绝并要求复核。原actionlint仍独立验证完整语法。

**验证入口。** [fayo-integration-gates.test.js](../V6_BO/tests/fayo-integration-gates.test.js)、原commit-check-triggers及github-actions-supply-chain测试；反例覆盖路径过滤、缺job、新风险脚本未接、注释冒充执行、忽略失败、dev缺失、条件跳过及不熟悉的YAML布局。工作树`npm run check`、原actionlint与定向测试已实际运行通过；最终SHA另登记。

**远端剩余。** 包含继承规则的ruleset列表读取为空；传统protection读取403，不能把权限错误单独解释成没有保护。有效规则汇总入口未取得回执。候选JSON的`active`不是远端生效证明；本聊天未修改GitHub管理规则。按[激活说明本轮补充](V6_RULESET_ACTIVATION_20261115.md)由原第一组核实真实拦截结果。
