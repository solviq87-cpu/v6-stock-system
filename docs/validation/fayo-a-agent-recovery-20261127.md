## 五项整改

1. 在调用研究作业之前，使用原独占写入器持久化失败形态的密封运行意图；意图未成功写入及核验时不调用作业。
2. 研究中断或日志写入结果不确定时，保留原意图。恢复调用只核对对应历史事件；未有事件则补记失败，已有匹配事件则返回原回执，不重新运行。未完成核对前不提供可确认的失败事件指纹；核对后仍沿用原人工失败确认门禁。
3. 运行期间复核历史前缀、当前意图及锁文件身份，在追加日志之前和之后检查；发现日志截断、重新封装替换、锁被替换或对应记录冲突则停止，不擅自删除他人的锁。
4. 对精确匹配历史已完成输入或结算指纹的非相邻重放拒绝再次执行；人工确认最近失败不授权旧完成输入重放。原相邻重复输入继续返回 unchanged。
5. 作业返回对象的 then 访问器异常改为持久记录失败，而非留下可自动重试的异常；无数据时不创建运行意图。预览仍不写入。

## 恢复与验收边界

崩溃留下的锁不会自动删除；必须由操作方确认进程退出、核实私有研究产物并按原操作约束处理残留锁。首次执行恢复不重新派发研究作业；未确认失败仍拒绝重试。正在运行或未核对的意图保守显示审计状态，未区分进程存活。尚未验证所有真实文件系统断电语义、原原子写入器组合、生产工作进程、原 CLI/watch 与双端状态展示；无外部可信锚点，拥有全目录写权限者同时删除或重写意图及完整日志链的情形不能保证检测。本批精确指纹去重不代表跨日期、跨算法版本或语义等价输入的全面去重，不保证真实训练内部副作用恰好一次。不能将未执行全量 CI 冒充整体验收。总管需先纳入 #486，再纳入本批独立增量，核对其他开放候选并运行原完整套件及组合回归；不合并、不部署、不自动改动生产权重。
