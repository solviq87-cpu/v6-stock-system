## 五项修复
1. 业务回执码须是安全整数，所有出现的业务码别名均校验；异常码不认作已确认拒绝。
2. 两个业务码不一致时（包括不同非零码）保留未知，避免选择有利于重试的限频码。
3. 当调用方实际提供HTTP 4xx的业务正文时，业务成功码与HTTP拒绝矛盾则未知；保留原无正文HTTP 429明确拒绝。不会凭空补出未传递的正文。
4. 限频文本只接受原字符串，核对两个说明字段；矛盾限频说明、传输不确定信息、业务成功与限频冲突均返回未知。正常明确拒绝和成功保持，分类输出不回显原正文或私密凭据。
5. 只读投递流水逐项检查error/detail，成功标签与失败/异常/未知证据矛盾时不标为网关受理，接收端始终未确认。保留原status、历史行、pushLogKey与合并去重语义。
