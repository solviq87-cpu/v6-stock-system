## 五项局部整改
1. 资金历史连续性按既有研究交易日历给出的所需日期核对，而非凭行数判完整；缺日/主力净额未知标partial并返回missingSessions；日历不可用时连续性未知，不按自然日或工作日推测。默认读取原 research-calendar-source；新增可注入日历读取器仅是原入口测试/操作者依赖，不认证日历或市场交易。
2. 明确历史截止日早于现有最新交易日历会话时，不再发起无法回答该历史时点的固定最新窗口请求；保持合法历史缓存原始日期与来源。重启式预置缓存重新计算覆盖状态，旧无序或超过原窗口的记录只返回规范化有界日期窗口；规范旧Map数组引用兼容保留，不宣称已消除所有外部可变引用。
3. 实际请求证券必须为六位字符串；显式code/symbol及各金额分项须匹配证券、合法数值。新增整个回执窗口接收高水位，避免无重叠旧回执以更新日期替换此前较新接收证据；原单日来源、单位、时点、同回执冲突检查不变。
4. 统一同实例时钟高水位与epoch，派发前和接收后检查，发现异常回拨、无效时钟或跨中国市场日期时拒绝旧请求写入。其他并发调用已检测的回拨不能被随后恢复的时钟抹掉；故障路径安全采样，保留经当前时点校验的旧记录或null。原同代码在途合并及15分钟限频保留。
5. 缺口诊断状态包含明确研究日历口径、所需交易日/缺失日、未外部认证标志；返回状态副本防诊断数组被外部篡改。未授予交易资格。
