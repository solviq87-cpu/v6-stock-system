## 五项局部整改
1. 公开行情采集明确 HTTP 200 且 ok===true 才可解析。206 等异常成功码保留 HTTP 错误，原公开探测器不会重试此类错误；原 403/429、重定向和一次传输重试规则保留。
2. 复用同一个有界原始字节读取器，严格验证声明长度及实际解码字节上限，未压缩响应必须长度一致；保留压缩响应传输长度差异。供应商文字解码拒绝无效 UTF-8/GB18030。不同入口原 256KiB、64KiB 上限保持。
3. 采集实例及跨重试检查共用单调的整数毫秒高水位，异常时钟禁止批次发表；异常后的同一采集实例保持失败关闭，需要重新建立独立可信检查。健康检查对响应间及发布时回拨保留失败诊断、撤下所有报价，不将剩余正常数据误标有效。
4. 公开检查的持久化投影要求规范整数时点；已标记 stale-or-invalid 的原拒绝快照只能显示带日期快照，不能凭读取时年龄重新成为新鲜证据。保持原 15 秒新鲜度、供应商时点、历史只读。
5. 双源核验绑定实际请求证券及确切腾讯/东财两源范围。健康诊断记录 partial-fresh / all-denied-or-limited 等实际共同失败观测，明确 commonCauseVerified=false；不推断供应商同根故障、不提升授权或交易能力。
