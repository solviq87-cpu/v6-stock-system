## 有限复核证据

- 精准执行新增缺失根因、2→1→2、原有 3→4 及旧记录迁移相关用例，实际 4/4 通过、0 失败、退出 0。命令及完整输出见 `review-result.json`、`precise-regression.tap`。
- 通过 `git show` 取得父 PR #359 的真实 `risk-alert-lifecycle.js`，用原 loader 只读打开包含新 `levelChanges`、`notificationAdmission`、`bypassGeneralCooldown` 的隔离日志。读取成功，两个生命周期事件及一条降级历史保留，文件字节未变化；新 loader 再读仍为二级并显示冷却。脚本与结果为 `check-previous-loader.js`、`previous-loader-result.json`。该结论仅覆盖读取格式兼容，没有模拟生产回切。
- 静态核对 `risk-state-contract.js`：无法评估与未命中分开；风险、证据、数据、动作分别输出；缺失数据不能据此解除；有效降级和解除要求晚于上次有效风险的证据，原规则仍需同规则及同版本通过回执；账户事故与报价事故要求对应恢复证据。
- 静态核对生命周期与 runtime：账户及账户期间由外层身份校验隔离；原书账、报价和权限仍从既有权威入口读取。原时点保留，刷新时点没有被替换为旧行情的原始时点。历史根因回填只形成无法评估的派生行，没有发出新交易许可。
- 静态核对通知：每日限额和普通冷却分别持久记录原因；入队、网关受理、接收端确认仍分开，未确认结果不自动重试。旧 loader 的读取兼容未通过增加新的生命周期事件枚举实现。
- 原 `V6_BO/server.js` 相对父版本没有差异。风险 GET/POST 仍要求编辑者授权；异步返回再次核验授权；POST 限定查看/静音字段，副本不能写。runtime 更新和发送前仍校验主角色、授权或私密通道条件，UI 仍只调用已有受保护风险接口。没有新增交易或设备授权入口。
