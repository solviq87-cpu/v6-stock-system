## 缺陷与修复

指数双源已在实际调用前复核时钟与交易日epoch，但原冷却和回执下限仍使用排队时点。延迟调度可以使成功或失败的请求在真正调用后不到5000ms再次发起，也可让早于本轮调用的本地接收回执进入指数观察视图。时钟回拨清空epoch后仍可能绕过原冷却。

本次保留排队时的保守预留，并在实际调用注入采集器前按已复核时点更新本渠道与跨epoch请求下限。回执必须不早于该次采集器调用；原始quoteAt允许早于调用，仍按原观察、错日、冲突、未来时间及只读规则处理，不将调用或接收时间冒充供应商报价时间。此处是应用层采集器调用时点，不声称测得真实底层网络发包时间。
