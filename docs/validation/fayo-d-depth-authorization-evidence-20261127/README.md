## 官方接口范围核对
- 迅投官方 XtQuant.XtData 文档：https://dict.thinktrader.net/nativeApi/xtdata.html 。普通 tick 与 l2quote/l2transaction/l2order/l2orderqueue 不同；获取 LV2 需要数据终端权限。实时 Level-2 接口并不自动提供跨交易日保存。原始 l2transaction.tradeFlag 中 3 为深交所撤单，深交所成交标志不能用来推导主动买卖方向。
- iTick 股票 WebSocket 文档：https://docs.itick.org/en/websocket/stocks 。depth、quote 与 tick 订阅类别不同，需要认证且受订阅套餐限制。现有 itick-stock-quote.js 只是普通报价路由，不能据文档存在即声称深度接口已接入、已免费或已获授权。
- 保留原122条来源登记与六图 miniqmt.l2 记录，不新增重复目录或擅自启用客户端/订阅。不确认用户当前付费套餐、终端授权、历史覆盖或独立许可。公开竞价、普通分笔、分钟K只能作为各自粒度的降级研究，不替代完整盘口、逐笔委托或队列。

## 五项局部整改
1. 在既有研究入口复核声明授权：实际来源、粒度、授权有效起止、撤销时点、原始报价与实际接收时点，以及显式证券/市场范围必须吻合；使用原来源目录阻断普通报价/日线/分钟等已知不相容路线冒充Level-2。既有独立导入声明仍仅为未认证研究材料，authorizationIndependentlyVerified=false。
2. 每个盘口档位的显式证券、来源、币种、复权/数量单位、原始时点与接收证据须和父回执匹配，检查价格、排序、交叉盘口、整数股数和数值范围；无效盘口不能标当前有效，完整深度/队列位置未知。
3. 每笔成交的原时间须落在声明授权期、同证券交易日及父观察范围内；校验来源身份、时点、顺序、唯一成交ID、金额安全与数量，排除撤单/非成交；MiniQMT 撤单标志3不得计入成交，深交所原始 tradeFlag 不得直接推断主动方向。未知/矛盾方向保留null，不用价格变化估算。
4. 独立区分父报价新鲜度和最后实际逐笔成交时间，旧逐笔样本不会因为父报价更新而升格；无效/超限逐笔记录不抹掉同批有效其他证券；逐笔和盘口结果均明确非完整交易所成交带/完整订单簿。
5. 竞价内部样本不能晚于父原报价及原接收时点，逐条原始与接收时点须在授权窗口内，沿用原竞价研究规则；不让后来追加的撮合结果改写既有回执。仍不推断真实委托队列、主力意图或交易许可。
