二、已完成的优化项

P0 竞价评分权重重构（server.js）

问题：「竞价涨幅黄金区」覆盖 88.4% 样本、命中率 12.6%≈全A 基线 12.8%，几乎没有排序信息量，却在 auctionScoreOf 中占 +26 分主导地位；真正有区分度的题材梯队类因子权重偏低。

做法：

  • 竞价涨幅黄金区：+26 → +10
  • 强势高开：+20 → +8；高位：+11 → +5；近一字：+3 → +2；温和：+10 → +4
  • 板块龙头：+8 → +14；板块龙二：+6 → +10；板块中军：+4 → +8
  • 连板惯性：max +10 → max +16（(lb-1)*4 → (lb-1)*6）
  • 小盘易拉：+8 → +12；中小盘：+3 → +6
好处：排序从「谁涨幅在 2~5.5%」这种常数基差，转向「谁在题材梯队中有真实地位」，auczt 选股质量应提升；权重结构与实证区分度对齐（连板惯性 41.7%、板块龙头 32.5%、中军 31.6%、小盘 21.4%）。
风险/未验证：权重调整后 score 分布变了，但 inferZTProb 的 score→prob 映射未同步重标；aucztHonestProb 会把 prob 压到 9~20%，最终推送 prob 诚实性不受影响，但「多少分算高」的排序阈值可能需再观察实盘样本后微调。
P1 auczt 回测两口径并列（_backtest_nd.js）

问题：auczt 预测的是「当日封板」，而 _backtest_nd.js 之前只展示「次日 +3% / 次日涨停」，读报告容易把 auczt 和 yier/lianban 的口径混为一谈。

做法：在 backtest 中对 auczt 额外计算 resolved 口径的「当日封板率」，与 nd 口径并列展示；trend 块同时显示 +3% 和当日封板率。

好处：避免决策口径错配；auczt 的真实预测目标（当日封板）与历史回验口径（nd）在报告中一眼可区分。
风险/未验证：resolved 口径依赖 s.resolved，非 void 但 unresolved 的 auczt 样本不计入；trend 中 dUp 可能因回填进度而波动。
P1 K 线派生涨停补漏能力（_zt_pool_enrich.js · 新建）

问题：_audit_zt_pool.js 已能发现数据源漏票（如 2026-10-16 的 000678、002531），但能力散落在审计脚本里，没有可复用的 enrichment 入口。

做法：封装 detectMissed / saveMissedReport / mergeMissedIntoPool 三个接口；默认只生成 zt_pool_missed.json 报告，--merge 才生成 enriched 快照，不自动改原池。

好处：把漏票检测从「一次性审计」升级为「可定时运行的能力」，为后续自动化补漏留好开关；默认不启用，避免覆盖范围外误差污染涨停池。
风险/未验证：漏票判定只覆盖 .kline_cache 内约 5900 只，不是全 A；--merge 生成的 enriched 快照需人工复核后再决定是否替换生产池。
P1 邮件通道独立心跳（_mail_heartbeat.js · 新建）

问题：邮件作为飞书备用通道，只有真正推送时才走 SMTP，通道何时失效不可知。

做法：独立脚本，默认只做 SMTP 登录+RCPT 验证（不发邮件打扰用户），加 --send 才发一封心跳邮件；结果写入 mail_heartbeat.json。

好处：可定时跑心跳提前发现邮件通道故障；产物可供面板展示「邮件通道健康/未配置/失效」。
风险/未验证：当前 config.json 中 qqMail 为空，心跳会报「未配置」；未接入 automation/server 启动链，需用户配置邮件后再启用。
