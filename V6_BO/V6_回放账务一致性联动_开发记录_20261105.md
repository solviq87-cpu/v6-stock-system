# V6 回放账务一致性联动开发记录

日期：2026-11-05

## 本轮修改

- `src/core/paper-replay.js` 引入既有只读三方账务对账器 `reconcilePaperAccount`。
- 对回放过程中实际成交的订单建立只读流水视图，使用成交日、成交方向、证券代码、股数、成交金额和费用重建现金及 FIFO 持仓成本。
- 在回放报告中新增 `accountReconciliation`，明确标记 `offline-paper-replay-read-only` 与 `canTrade: false`。
- 成交订单增加可核对的 `amount` 字段。
- 新增测试验证回放报告包含完整、通过且不可交易的账务对账摘要。

## 边界与未完成项

- 本轮联动的是离线历史回放报告，不是实盘或持续运行的券商模拟撮合服务。
- 现有 `paper-shadow-reconciliation` 模块没有在生产订单结算入口中被调用；当前工程的 `paper-service` 是只读 HTTP 服务，`paper-session` 是离线回放账户。不能声称已经接入真实订单生命周期。
- 当前样例回放测试数据未产生实际成交，因此专项断言验证了空成交账户的对账一致性；需要增加必然成交的可控历史样本，覆盖买入、卖出、费用、持仓成本和现金变化。
- 需要优化或拆分全量测试执行，取得完整退出码和最终汇总后才能完成全量验收。

## 安全说明

此功能只做只读核对，不改变订单、账户或持仓，不授权真实交易，不构成实盘交易能力。
