# 卡片部署、数据来源与飞书通道

核对基线：`461c62816a6e41cfff96fced6aeb1a6dabfba080`。参考为用户提供的源码索引中已读取的 `server.js`、`em.js`、`public/index.html`、`public/assets/app.js` 等文件；不复制该工程的私有配置。

## 卡片不是单独部署的服务

参考工程由 Node `server.js` 提供页面和接口，页面 `public/index.html` 引入 `/assets/app.js`。浏览器读取同源 `/api/state`，通过 `/api/stream` 的 SSE 更新；股票卡片由页面脚本把后端字段渲染出来，不需要逐张购买或部署服务器。手机和电脑可分别连接同一后端。

| 卡片 | 后台结果 | 上游与处理 |
| --- | --- | --- |
| 涨停池 | `S.ztPool` | `em.fetchZTPool` 等读取东财涨停池，已有同花顺等备用和完整性补充；带板数、封单、开板次数、板块和数据日 |
| 复盘 | `S.review` | 涨停名单 + K 线形态 + 快照 + 板块角色；持久化 `review.json` |
| 精选池 | `S.candidatePool` | 全市场行情预筛，再补 K 线及资金，执行 `rebuildPool` 多路径规则和评分 |
| 趋势池 | `S.trendPool`、趋势扫描结果 | K 线趋势、资金与学习库；研究条件和评分不代表已验证的胜率 |
| 一进二、连板接力 | `S.yierList`、`S.lianbanList` | `scanYiEr` / `scanLianbanRelay`；`refreshStrategyCards` 独立更新展示，`strategy_cards.json` 保存列表及数据日期 |

东财是原工程行情/K 线/涨停池等主要来源，腾讯用于部分报价回退，同花顺用于部分涨停题材与备用数据。具体回退由 `em.js` 和现有数据门禁控制，不保证每家此刻均可访问。本次没有为验证推送而联网抓取行情、制造选股结果或伪造资金字段。

卡片展示与手机外发各自受控：推送额度、静默或去重拦截不应清空卡片；看得到卡片也不代表手机已收到消息。

## 与当前静态发布目标的区别

`V6_WEB/workbuddy/index.html` 是唯一 WorkBuddy 目标使用的独立单文件前端，含浏览器采集、公开快照研究及同源 records 持久化。它与 BO 的 Node 服务不是同一部署形态。静态 HTML 更新不会自动获得 `/api/state`、`/api/stream` 或 Node 推送定时器。

运行上述 BO 卡片和自动飞书推送需要 HTTPS 后端、持久化数据目录和唯一主推送实例。手机/电脑只负责展示和操作；不能将机器人 Webhook 或签名密钥放进公开 HTML、浏览器本地存储或共享 records。当前任务未采购或部署新的后端主机，也未更换发布目标。

## 推送渠道与本次接线修复

原工程已有飞书自定义机器人、QQ 邮件和页面 SSE。默认业务消息走飞书私密通道；只有明确的公开消息才使用公开通道及原邮件分支，私密失败不转公共群或邮件。网页 SSE 只更新在线页面，不能代替手机离线通知。

本次修复现有飞书接线，而不是新建一套绕开原去重规则的发送器：

1. 修正签名：HMAC-SHA256 的 key 为 `timestamp + "\n" + secret`，消息为空字符串，再 Base64 编码。参考：[飞书官方自定义机器人文档](https://open.feishu.cn/document/client-docs/bot-v3/add-custom-bot)。旧实现把密钥和消息用反，开启签名时可能被拒绝。
2. 普通私密业务推送、源码包私密通道和自检读取运行环境中的私密签名密钥；公开发送和自检读取公开签名密钥。保留原配置文件回退。
3. 公开通道体检默认使用实际生效的环境地址；体检新机器人时不擅自复用旧机器人的密钥，须由该次请求显式提供新密钥。
4. 推送诊断以实际默认私密通道为依据，不再因只有公共/邮件配置就宣称默认推送可用，也不把“配置存在”说成“手机已送达”。

## 管理员配置

在真正运行 Node 的主实例私密环境配置中设置，或通过已有编辑者权限面板保存。以下只列名称，不含任何凭据值：

| 用途 | 环境变量 | 原配置字段 |
| --- | --- | --- |
| 本人私密机器人地址 | `V6_FEISHU_PRIVATE_WEBHOOK` | `feishuSecWebhook` |
| 私密机器人签名密钥（该机器人启用签名时需要） | `V6_FEISHU_PRIVATE_SECRET` | `feishuSecSecret` |
| 可选公开机器人地址 | `V6_FEISHU_PUBLIC_WEBHOOK` | `feishuWebhook` |
| 可选公开签名密钥 | `V6_FEISHU_PUBLIC_SECRET` | `feishuSecret` |

普通选股消息默认私密，因此应先配本人专用机器人。不要把 WorkBuddy 站点分享码填成 Webhook。在 GitHub Actions 填入变量也不会自动配置一个尚未部署的 Node 主实例。

填写并重启主实例后，由管理员在后端面板主动执行通道自检，核对对应机器人的网关回执，再在手机飞书中核对接收情况。首次真实外发前需要确认收件机器人属于本人；此次没有发送真实消息。环境中未发现 `V6_FEISHU_*` 配置，不能宣称已接通个人机器人。
