## 本轮修改

| 文件 | 修改 |
|---|---|
| `src/core/process-file-lock.js` | 新增进程锁工具。锁文件记录持有PID；检测到持有进程已退出时允许安全回收，活动进程及无法核验的锁均拒绝自动清理。 |
| `src/core/paper-account-ledger.js` | 接入可回收进程锁；增加默认关闭的可选故障注入回调，可在写入前、临时文件写入中、原子替换后触发测试故障。未配置回调时仍走原子临时文件写入、fsync、rename、目录fsync流程。 |
| `src/core/paper-transaction-coordinator.js` | 事务锁接入进程锁，进程异常退出后可安全恢复；事务日志仍以SHA-256指纹校验，账本成交以eventId幂等。 |
| `tests/paper-account-multiprocess.test.js` | 新增两个独立Node进程重复成交事件测试，以及两个不同订单争用资金测试。 |
| `tests/paper-crash-recovery.test.js` | 新增子进程在提交前、临时文件写入中、账本提交后响应前被SIGKILL的恢复测试；新增损坏权威账本拒绝恢复测试。 |
| `tests/paper-multiday-reconciliation.test.js` | 新增跨日持久账本重建、重复事件重放、部分成交/撤单/T+1/冻结资金的确定性多日测试。 |
| `tests/paper-account-ledger.test.js` | 活动锁测试夹具改为写入当前进程PID，匹配新的锁协议。 |

```bash
node --test tests/paper-account-multiprocess.test.js
```

结果：2/2通过。

- 两个独立进程同时提交相同订单成交事件，最终只保留一条账务事件；并发拒绝后重试保持幂等。
- 两个独立进程以不同订单争用同一账户现金，账户现金不为负，成交事件与现金变化守恒，不发生超额使用资金或丢失更新。
- 锁冲突时允许明确拒绝写入；不承诺排队等待。

## 任务二：提交故障恢复

执行命令：

```bash
node --test tests/paper-crash-recovery.test.js
```

结果：4/4通过。

- 提交前SIGKILL：只留下prepared事务，恢复后完整提交一次。
- 原子临时文件写入中SIGKILL：留下不完整临时文件，原权威文件不被半写覆盖；恢复后完整提交一次。
- 账本原子替换后、事务响应/标记完成前SIGKILL：恢复识别已存在的eventId，不重复扣款。
- 权威账本内容损坏：恢复报错并保留损坏文件原文，不静默初始化空账本。
- 进程退出遗留的账户锁和事务锁可在确认PID已不存在后回收；无法核验的锁保持拒绝。

## 限制与未解决事项

1. 多日账务事件账本跨服务对象重建已测；订单生命周期状态机本身仍为独立内存组件。本轮确定性多日生命周期测试通过操作序列重放，不等同于未完成订单状态已持久化接入所有HTTP/策略入口。
2. 本轮是本地合成数据和SIGKILL故障注入，不是真实行情驱动、券商账务核验、生产环境或真机验收。
3. 进程锁在当前Linux/Node环境验证；Windows/macOS和网络文件系统语义仍需专项兼容测试。无法核验的旧锁会拒绝自动清理，需人工核验。
4. 主账户统一订单接口与双端页面完整端到端联动仍需独立验收；独立研究入口维持隔离，未将离线实验接口改成主账户入口。
5. 电脑浏览器/iOS/Android真机、真实行情供应商授权、短信OTP、HTTPS、多用户云端部署、灾备RPO/RTO仍未验收。

## 安全边界

- 所有测试均为离线模拟账户；`brokerConnected=false`。
- 没有执行真实券商交易或真实自动下单。
- 本轮没有修改双端UI功能，也没有合并独立研究入口到账户主链路。
- 675是本轮全量Node测试运行器结果，不与历史批次数字累加。
