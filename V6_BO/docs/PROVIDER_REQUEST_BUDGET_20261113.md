# 供应商请求预算与限制响应

基线：`b434769fde9301ed91c1cd46777b9af4b7e002e2`。本补丁收口 `em.js` 的真实请求尝试；不改变主页、策略阈值、报价来源时点或授权状态，不部署。

## 实际约束

`src/core/market-request-governor.js` 的生产单例按供应商家族共享队列：东财全部子域同组，腾讯 `gtimg.cn`/`gtimg.com`/`qq.com` 同组，新浪和同花顺各组，未知域名共用保守组。默认同组相邻起步至少1000ms、最多1个在途、最多100个排队、每项排队最多30秒。起步预留同步完成，多个定时器同时唤醒不会共享旧时间戳而一起发出。超期任务删除，不在后续补发。

每个 Node 请求、分页重试、现有 curl 备用、腾讯/新浪/同花顺请求和指数请求都经过 `run()`。普通网络错误最多3次 Node 尝试，重试也占同一预算。移除数字子域轮换；403/429不重试、不换域名、不转curl、不继续下一个供应商。排队中的同家族请求立即失败，新请求在冷却期不发。

429至少冷却60秒，403至少15分钟，合法且更长的 `Retry-After`（秒数或HTTP日期）延长窗口。此预算是项目保守默认，不是供应商认可频率，也不能保证不会限制访问。

生产单例将限制窗口保存在私有目录（`V6_MARKET_REQUEST_STATE_DIR`，未设置时为用户私有目录下 `.v6-private/market-requests`）。文件只记录schema版本、固定家族标识、状态码和冷却终点，不保存URL、请求参数、响应头或凭据。目录0700、文件0600，拒绝符号链接；只有限制事件写入，普通成功不创建状态文件。每次发送前重读有效窗口。损坏、未知版本、不安全权限或写入失败使本进程停止发送，不能因重启或读错就恢复流量。

该文件协调已知冷却窗口；**启动间隔和在途数量仍是单进程预算**。多主进程若共用出口，不得宣称拥有跨进程全局速率锁；应由运行调度保证唯一采集主实例。

限制写入使用私有排他锁并在锁内重新合并窗口，防止较短窗口覆盖另一进程已保存的较长窗口。状态异常或残留锁需要停止相关采集进程，确认没有写入者，人工检查/修复权限与文件，再清理确认失效的锁后重启；保留有效冷却文件，不自动抢锁或删除冷却。

## 现有功能与吞吐取舍

- `fetchKlineBulk`复用`fetchKline(code, days)`，批量和单票同参共享同一个在途Promise。仍要求至少6根才计批量成功。以前批量专用分支会在东财返回1至5根时再取其他源；现在遵循单票既有来源选择，该不足6根结果记失败，不以额外来源拼接或虚构历史。
- 全A东财60页在1秒间隔下需要至少59秒加传输时间；将该轮停止派页预算由30秒调为120秒，否则健康数据也结构上无法达到4000条完整阈值。新浪每100只一页及腾讯每60只一批同样受到供应商预算。全量行情会更慢；客户端继续显示真实数据日期，旧报价不得借新的获取时刻取得交易资格。
- 排队超时、限制窗口或上游故障仍可使本轮数据缺失。已有缓存保留与过时标记由消费层处理，不填0、不制造新原时点。
- curl不再覆盖系统代理环境；读取有界状态/响应头/响应体，临时文件结束后清理，清理失败不覆盖限制异常。超时或部分传输即使附带200也不当成成功数据。

## 离线验证

新增 `tests/market-request-governor.test.js` 与 `tests/em-request-budget.test.js`，使用假时钟、假Node wire、假curl和临时私有目录。覆盖并发起步、队列容量/期限、已排队冷却、403/429/Retry-After、重启窗口、持久化失败封闭、健康60页、K线去重、curl错误边界、原报价时点保留。沿用 `tests/batch-quote-publication.test.js` 的15秒最终发布检查。

专项运行应加载会拒绝真实网络和非允许子进程的preload，再运行 `node --test --test-isolation=none`。这些mock验证不证明供应商认可该频率或生产持续可用。

回滚应撤销本补丁提交，并评估旧版本会丢失限制保护的风险；私有冷却记录不应随代码回滚删除。
