# V6 策略研究与模拟盘只读对账｜开发与测试报告

日期：2026-11-05

## 本轮目标

把四套策略的独立研究证据与模拟盘回放结果建立可审计的只读对账关系，识别信号与模拟盘订单在股票、执行日期上的对应情况，同时避免把“同日匹配”误称为策略驱动或真实成交。

## 新增实现

文件：`src/core/strategy-paper-reconciliation.js`

导出：`reconcileStrategyWithPaper(strategyReplay, paperReport)`。

实现要点：

1. 只接受 `audited-strategy-evidence-replay` 与 `offline-paper-replay` 两类明确报告。
2. 强制两个报告的数据集 SHA-256 指纹完全一致；不同数据集直接拒绝对账。
3. 对每套策略分别按股票代码、信号对应的下一交易日执行日期，核对模拟盘买入订单。
4. 将结果区分为：`filled-match`、`execution-blocked`、`risk-paused`、`picked-not-filled`、`no-paper-match`、`no-next-session`、`not-actionable`。
5. 额外列出模拟盘有买入成交、但没有四套策略同股票同执行日通过信号的记录。
6. 输出只读报告，`canTrade=false`、`verifiedLive=false`，不修改账户、持仓、资金或订单。
7. 明确说明这只是独立系统的事后对照，不证明模拟盘由四套策略驱动，也不代表真实可成交或实盘收益。

## 新增测试

文件：`tests/strategy-paper-reconciliation.test.js`

新增4项测试：

- 同股票同执行日匹配成交，同时明确不推断因果关系。
- 数据指纹不同必须拒绝对账。
- 区分风控暂停、已选未成交、成交阻断和无匹配。
- 拒绝不完整或错误的报告契约。

## 未完成与限制

- 本轮实现的是策略研究报告与模拟盘回放报告之间的只读核对，不会改变现有模拟盘选股逻辑。
- 只有在两份报告由同一份历史数据集生成时才允许比较；生产真实行情、真实券商成交回报仍未接入。
- 真实授权历史行情、四套策略真实样本外有效性、生产部署、iOS/Android 真机视觉验收仍需单独完成。
- 483项自动化测试通过不等于十一大工程全部正式验收。

## 命令行使用

先分别导出同一数据集生成的策略回放 JSON 与模拟盘回放 JSON，再执行：

```bash
npm run reconcile:strategy-paper -- strategy-replay.json paper-replay.json
```

结果输出到标准输出；输入文件超过100MB或数据指纹不一致会拒绝处理。该命令只读，不写回账户。
