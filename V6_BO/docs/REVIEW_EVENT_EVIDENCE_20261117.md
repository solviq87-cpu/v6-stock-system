# 天枢智策 V6 · 涨停逐股事件证据卡（2026-11-17）

## 本次改动
- **原位增量修改**：沿用「每日复盘 · 涨停形态与归因」原有卡片、选股、分组、双端共用网页，不重建页面，不调整交易账户/策略/价格/推送链路。
- 区分「同花顺 reason_type 题材标签」、「封单换手等盘面结构推断」和「公司具体事件的来源证据」。题材词不再被直接描述成经核实的涨停原因。
- 每只复盘股票可点击「逐股事件 · 日期与来源」，调用已有只读接口 /api/research/news-evidence?symbol=（保持当前登录权限）查询已归档新闻，显示源头名称、供应商发布时间、系统收录时间、归档时间、摘要与可用的原文链接。
- 用对应复盘日 **北京时间 15:00** 为时间门槛。收盘后发布、后归档、原始时间未知、超过7日旧闻、已撤稿/被修订数据明确单列，不得冒充当日盘中证据。即使盘中前已收录，也只称「关联线索」而非因果验证。
- 任何字段缺失、接口未授权/不可用、证据为零，直接展示未知；不填充假日期、虚构公告或推断已核实，不自动买卖或提高推荐概率。
- **事件发生日 ≠ 新闻发布时间**，无可核验事件日期时显示“未核实”；关联证券代码也不等于公司合同/实际业务关联，明确展示“业务关联未核实”。
- 原文链接仅允许 http(s) 且不带凭证，DOM 用 textContent 呈现外部内容；登录 token 仅放在 Authorization 头中，不进入链接和展示。

## 与现有工程的兼容方式
- `index.html`、`app.js` 和主 CI 工作流恢复为既定冻结基线，避免旧版恢复证据的 SHA 错误。
- 原页面已加载的 `ui-navigation.js` 负责异步装载新证据组件；利用 `MutationObserver` 为重新绘制的复盘卡片添加按钮，不改变原渲染数据与策略代码。
- 证据详情保存在 `#review` 重绘节点**外侧**，避免 5 秒自动刷新抹掉展开内容；页面隐藏、断线或角色变化会清空敏感结果。
- 新功能的请求使用同源绝对 URL 和 `Authorization` 请求头，绕过旧版对相对 `/api/` URL 自动附加令牌的兼容逻辑；不改变原全局认证实现。
- 目前按钮位于电脑/手机浏览器均可访问的完整复盘页；独立的 `/m` 精简首页并未添加另一套重复复盘。

## 未完成事项与限制
- 当前接的是已存在的 **新闻证据归档**，尚未建立完整的巨潮/交易所公告正文、公告事件发生日、证券业务关联、跨来源核验链路。不能称作“已确认所有涨停原因”。
- 单一新闻提及某股 ≠ 该消息导致涨停；供应商日期不等于经过第三方时间认证。数据仅研究展示，不可推导可交易性。
- 既有 /api/research/news-evidence 一次最多返回 50 条归档修订；遇大批量历史或更早版本，视图不是全量存量检索。
- 本次不修改历史涨停数量分母；数据源数量/样本覆盖和生产上线仍需单独核验。
