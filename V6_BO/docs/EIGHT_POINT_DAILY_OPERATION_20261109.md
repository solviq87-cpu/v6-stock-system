# V6 八项每日持续运行闭环（同一次交付，2026-11-09）

## 目标
用户明确要求大盘、板块、个股联动、解释、风控、学习、公开策略分层、自动测试作为**一个完整日常链路**协同运行，不再分成八个互不相干的版本。本变更复用已有 `complete-workbench` 与 `eight-point-research-pipeline`，让每次历史样本评估都保留八项证据，并新增**本机跨日观察池持久化**、公告/大跌保护和本机持仓风险汇总。

注意：**代码闭环 ≠ 真实行情验收、通知已送达、服务器已部署**。这三项尚须对应合法来源和用户真实环境，不能由离线 CI 自动代替。

## 一次性本地运行
将已有的历史研究输入保存在你电脑的私人目录，使用官方合法途径取得的数据，明确 `provider` / `datasetId` / `priceAdjustment`、每根K线日期和公司行为对账声明（声明不是外部认证）。根据使用情况选择：

```powershell
cd V6_BO
npm run research:eight -- "C:\\V6-private\\history-input.json" --watch-state "C:\\V6-private\\watch-state.json" --holding-watch "C:\\V6-private\\holdings.json"
```

- 只提供第一个输入文件：执行一次性只读完整八项历史研究，**不修改磁盘观察池**。
- 增加 `--watch-state`：读取上次的历史研究观察状态，验证来源与企业行为声明、全部规则和双账核对完成后，再把当次状态保存至本机指定私有路径。父目录必须事先存在，**路径必须为绝对路径、无软链接**。同一日期同一输入完全幂等；旧交易日或同日修改的数据被拒绝，必须先人工核对。写入采用排他锁、私有文件权限、临时文件落盘与原子替换。
- 增加 `--holding-watch`：读取同机独立手动持仓文件和最多两份来源自报报价，仅将仓位数、有效报价数、风险数量、报价冲突数汇入八项风险**汇总**。**不输出持仓股票代码、成本、股数、报价、个人账户或通知目标**；浮亏时效依旧要求逐票报价原始时点在15秒内，数据缺失不补零。
- 观察池文件是独立本地隐私数据，禁止推送到 GitHub、分享站点或容器公共日志；与模拟盘权威账本和订单完全隔离。

## 本轮八项实际联动
1. **大盘**：保留同一历史交易日已导入的上证/深证/创业板+A50（辅助）指数变动、宽度覆盖、数据源和缺数状态。
2. **板块**：保留同日来源声明的板块强弱、样本内RPS、弱市避让银行/保险/证券/白酒的研究降序，只影响观察次序。
3. **个股与观察池**：任一符合条件的战法可以入观察；不同导入日期的信号可提升关注，失去当日数据不自动晋级、不抹掉上次有效状态。跨日状态可用私有 `--watch-state` 持久化，报告仍不冒充实时盯盘。
4. **入选解释**：原规则和新增研究战法证据、市场/板块同期关系、风险清单及**巨潮资讯样式的历史公告标题线索**；公告必须不晚于评估时点、官方PDF地址格式匹配，正文未核实，始终不承认上涨因果。
5. **风控**：原T+1/费用/集中度与拒单不变；双账对账、数据异常标记与可选本机持仓风险摘要同屏，风险覆盖看涨信号，供应商报价未获独立认证。
6. **学习规则**：冻结5日多窗口研究评审与重复信号分段保留；传入同日期、同提供者、覆盖率有效的大盘急跌证据时，学习层标记暂缓调权复核、保留亏损与暴跌样本；缺数据不虚构大跌或“不可抗力”。
7. **公开策略分层**：原四策略完全保留，新增8条公开/联动/量价研究规则保持研究层，不能直接晋级正式交易。
8. **自动测试**：CI持续检查整套集成、跨日回放、公告前视保护、私人状态锁/损坏/回退、持仓隐私、双端展示与已有全量测试；PR和合并后dev均单独验收。

## 数据文件与外部验收
- 可选 `announcements` 数组必须为现有公告研究协议：`{code,title,source,publishedAt,url}`；发布时间不得晚于本次历史评估日15:00（北京时间），只有 `https://static.cninfo.com.cn/finalpage/YYYY-MM-DD/数字.pdf` 样式URL进入标题线索。URL格式本身不构成外部正文真实性认证。
- 可选 `marketShockContext` 使用现有 `assessMarketShock` 的完整校验协议；至少两个境内指数、可信时点和同提供者的涨跌家数等才可展示“暂缓学习复核”，但绝不修改原参数。
- 本地状态 `watch-state.json` 含股票代码与观察状态，属于**个人隐私**；哈希仅是完整性校验，不代表数字签名或防恶意篡改。恢复时先做安全备份，损坏或同日来源变更将拒绝覆盖，不自动重建或删除原件。锁残留时必须核实无并发进程并保留备份后人工处理。
- 因输入历史供应商、许可与真实行情尚未全面独立验证，`verifiedLive=false`、`productionReleaseReady=false`、`canTrade=false`、`canNotify=false`。持仓摘要只显示“本机风险已评估”，不表示提醒发送成功。
- 国内服务器、HTTPS、跨设备持久化、免费行情实盘连续采集、供应商授权、公告正文核对、短信/飞书送达和电脑/手机1:1真机视觉都需要**实际外部凭据和现场验收**。部署不要求先于核心代码，但不得悄悄标成完成。
