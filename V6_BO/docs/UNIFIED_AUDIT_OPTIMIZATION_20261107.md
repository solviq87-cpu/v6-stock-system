## 一、唯一产品目标
对外名称「天枢智策·AI智能量化选股系统」；内部仓库、代码路径和版本仍为V6，不做高风险整体重命名。

**双系统，严隔离：**
- 智能选股与及时推送：分析市场/板块/个股，解释推荐依据和风险，用户自行决定实盘操作。
- 全自动量化**模拟盘**：允许虚拟资金自动模拟买卖、记账、评估收益与回撤；**不得连接券商真实账户或发送真实订单**。

核心验收准则：**选得准、推得快、解释清楚、推得稳、持续改进。** 禁止以文档提交冒充代码完成、测试通过或部署上线。

- `src/core/strategy-engine.js`：缺失字段、空规则及缺失阈值存在静态可推导的误放行风险；`multi-strategy-engine.js` 依赖其pass结果，可能传递至评分。**尚未验证线上输入触发率。**
- `scripts/eastmoney-historical-import.js` 和 `src/core/eastmoney-historical-feed.js`：已有A股**日K线**导入和OHLCV检查；尚未确认分钟K线长期保存/回放。
- `scripts/continuous-research.js` 和 `src/core/continuous-research-ops.js`：输入变动后生成可复核研究档案；**不等于已具备自主模型训练与自动升级**。
- 现有模拟盘代码和15秒原始报价时点门禁需回归测试，不能为了新增学习能力放松时效门禁。
- 尚无本轮全量测试通过、自动学习闭环上线、服务器部署完成的证据。

## 四、按依赖排序的统一实施计划（每项必须有代码+测试证据）
**P0 稳定选股与行情（先做）**
1. 定位`evaluateRule/evaluateStrategy`真实调用与配置；添加缺失值、缺失阈值、空规则及正常输入的回归测试；确认无合法空规则后最小修复。**验收：异常输入不误选，正常策略输出与基线一致。**
2. 核验行情源、原始时间戳、停牌/涨跌停/缺失、复权与交易日一致性；不能用接收时间冒充报价时间。**验收：过期和缺失数据不会进入推荐或模拟成交。**

**P1 推送质量与模拟盘**
3. 核对选股排序、推送去重、冷却、重试、触发到送达延迟、推荐理由。**验收：有可复现的漏报/重复/延迟测试及日志。**
4. 验证模拟盘自动运行、虚拟资金、成交规则、滑点/费用、风险与恢复；禁止实盘连接。**验收：独立模拟账本与异常恢复测试。**

**P2 K线记忆与自动研究**
5. 审计日K/分钟K采集与持久化，补齐历史质量、来源、时间、复权、校验和与增量导入。**验收：同样输入可重复回放，不能凭空补造停牌K线。**
6. 冻结每次推荐时点/当时K线/策略版本；计算后续1/3/5/10交易日表现；建立时间序列训练/验证/测试隔离和样本外对照。**验收：无未来数据泄漏，报告可重放。**
7. 仅生成候选参数或策略，自动回测+模拟盘验证；正式策略的启用需对比原基线，保留回滚。**验收：样本外指标与失败案例明确，不自动覆盖正式策略。**

**P3 候选指标与开源借鉴**
8. 支撑阻力公式：冻结信号发生时的动态高低价，核验LONGCROSS语义；与无该指标的基线比较选股效果。**验收：无重绘式历史美化，不直接把提示文字当交易指令。**
9. 借鉴MIT项目的模块化/数据处理/研究设计，保留来源与版权声明；Backtrader仅研究架构，任何源码复用先做GPL兼容性评估。**验收：来源、许可证、变更与测试均可追溯。**

## 五、统一交付规则
每个任务必须报告：`问题/证据 → 修改的代码路径 → 测试命令与真实结果 → GitHub commit → 是否已部署`。
- 文档提交≠功能实现；代码提交≠测试通过；GitHub更新≠线上部署。
- 保留原有模块、策略、数据与配置；尽量小改动，先测后合并，防止负优化。
- 全量质量门禁按用户决定暂缓，先形成可靠回归基线。
- 无服务器前不宣称线上部署；用户的真实资金始终不受系统控制。
