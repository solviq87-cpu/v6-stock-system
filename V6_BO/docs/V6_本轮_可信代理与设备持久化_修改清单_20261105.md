# V6 统一主线续批：可信代理、防限流绕过与设备权限持久化

日期：2026-11-05。基线：`V6_统一主线_SSE即时撤权_完整工程_20261105.zip`。

## 本轮修改（仅列实际改动）

1. `src/server/trusted-proxy-ip.js`（新增）：默认只使用请求 TCP 对端地址，明确配置 `QD_TRUSTED_PROXY_IPS` 后才接受可信代理的 `X-Forwarded-For`；从右向左寻找第一个非可信节点；无效 IP、超长/格式异常的链路回退对端地址。不再用客户端随意提交的 XFF 轮换登录失败计数 IP。
2. `server.js`：认证限流和设备审计 IP 改走统一可信代理解析器；手动设备撤权和 `prune` 批量清理变更增加写盘失败回滚；`prune` 成功时注销受影响的只读短会话，并立即清除失效 SSE 连接。只读设备24小时回收原有逻辑保留。
3. `tests/trusted-proxy-client-ip.test.js`（新增）：直接连接、可信代理、多跳链、无效/过长头及 IPv4-mapped 等测试。
4. `tests/device-access-persistence.test.js`（新增）：注入持久化失败检查台账回滚、成功保留变更，静态审计撤权/批量清理与立即断流顺序。
5. `tests/research-live-http-isolated.test.js`：真实 QD_CLOUD 隔离 HTTP 用例增加不同伪造 XFF 头下的登录失败限流验证；非 root 环境模拟只读目录以验证撤权写盘失败时用户授权不被误删；移除 SSE 检测用例留下的29秒无用计时器，避免测试进程不退出。
6. 更新 README、统一大纲、未完成项、恢复检查点和测试原始输出。

## 云端部署重要注意事项
- 必须设置 `QD_CLOUD=1` 关闭本地回环免密。
- 如通过反向代理，确认代理实际 TCP 地址后**仅**把该地址加入 `QD_TRUSTED_PROXY_IPS`（逗号分隔，纯 IP）；例如代理在同一台主机上：`QD_TRUSTED_PROXY_IPS=127.0.0.1,::1`。不要把不可信的客户端网段加入其中。
- 反向代理必须向后端附加真实的 TCP 对端地址，而不是直接照搬客户端提交的 XFF；未配置可信代理则默认使用 TCP 对端地址，可能使同一代理后的多个用户共用一组限流桶，需在部署现场调试。
- 本批仅处理 IP 可信边界，**不证明**实际 HTTPS/TLS、WAF、负载均衡与生产限流已验收。
