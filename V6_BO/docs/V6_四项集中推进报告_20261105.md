## 本轮完成的代码工作

### 1. 四套策略原生信号产出
- 将既有 `src/core/native-strategy-daily-runner.js` 接入服务端统一研究入口 `POST /api/reference-strategy-research`。
- 入口按交易日逐日运行十四条规则、八字规则、GPT五策略因子评估及Python三轮证据校验。
- GPT缺少同日完整因子时返回 `unknown`；Python缺少独立原生执行证据时返回 `unknown`，不伪造策略信号。
- 研究接口仅允许 POST、要求编辑者权限、请求体上限8MB；不会写入模拟盘账户或触发真实订单。

### 2. 独立归因与样本外验证

- 使用 `splitDay` 划分样本内/样本外；按信号后交易日计算纸面成交估计，并纳入手续费、印花税和滑点。

- 输出明确标注 `canTrade:false`、`verifiedLive:false`，纸面收益不是实盘收益或可成交证明。

## API 使用约定

`POST /api/reference-strategy-research`

JSON字段：
- `history`：符合 `src/core/historical-validation.js` 约束的历史数据集。
- `snapshots`：可选，按 `股票代码/交易日` 索引的同日快照；必须包含匹配的 `symbol` 与 `observedThrough`。
- `pythonEvidence`：可选，按 `股票代码/交易日` 索引的Python三轮原生证据。
- `splitDay`：可选，样本内/样本外分界的交易日索引。

接口需要编辑者权限。缺少真实授权历史数据、同日GPT因子或Python执行证据时，不会生成虚假的通过信号。
