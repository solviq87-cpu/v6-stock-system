# V6 模拟盘订单资金事务协调与恢复报告

日期：2026-11-05

## 本轮改动

新增 `src/core/paper-transaction-coordinator.js`，以持久化 prepare/commit 事务日志协调订单成交与纸面账户资金/持仓账本。

执行顺序：
1. 校验事务 ID 并取得独占锁。
2. 将订单、成交事件、交易日期和 `prepared` 状态写入事务日志，原子替换并 fsync。
3. 调用账户账本 `transact`。账户账本按成交 `eventId` 幂等，重复重放不会重复扣款或增加持仓。
4. 将事务日志状态更新为 `committed`。
5. 若进程在第3步完成后、第4步前崩溃，重启执行恢复时重放第3步，账户账本识别已存在的相同事件并返回幂等结果，再将事务标记为 committed。

新增恢复命令：

```bash
npm run paper:transaction:recover -- <account.json> <transaction-journal-dir>
```

新增测试：`tests/paper-transaction-coordinator.test.js`，覆盖正常提交、模拟崩溃后恢复、事务 ID 内容冲突、事务日志篡改、非法事务 ID。

## 验证结果

- 事务协调及相关订单/账本专项：34/34通过。
- 全部测试文件 `node --test tests/*.test.js`：531/531通过，0失败，0跳过，约33秒。
- 本轮没有执行真实券商交易；所有功能均为离线模拟盘。

## 边界与未完成项

- 这是基于本地文件系统的可恢复事务协调，不等同于数据库原生跨表 ACID 事务；目录 fsync 的可用性受操作系统影响。
- 恢复流程要求事务日志目录与账户文件位于可靠、持久化的本地存储；多机共享文件系统和云盘并发语义尚未验收。
- 当前事务协调模块提供独立 API，尚未把所有现有 HTTP 订单成交入口统一迁移到该协调器；接入前不可宣称所有订单路径都受该事务保护。
- 尚需增加端到端 HTTP 崩溃注入、断电恢复、跨文件系统行为和长期连续运行测试。
- 未完成真实行情授权、真实策略样本外验证及双端真机视觉验收。
