# 历史回填访问预算（2026-11-13）

这是 `b434769` 的历史回填修复，不是线上部署结果。截图所含「已发现名单/历史指标可用/正在补全日线」等完整文案在本仓库未找到，截图页面及线上实际请求量未确认。

`server.js` 的 `klineBackfill` 是盘后、启动补算、健康补算和手动按钮共用的唯一入口。每轮最多60只、两轮起始至少60秒、所有时段合计每日最多6000只预留尝试；每只串行走 `em.fetchKline`，实际HTTP节奏另由供应商共享访问控制负责。取消原盘后30秒/2000只和绕日12000上限的通道，批失败不再立即重抓整批。日预算是代码尝试数，不能冒充精确HTTP请求数。

`V6_HISTORY_BACKFILL_DAILY_LIMIT` 可降低日预算；0关闭回填，非法值或超过6000也关闭，0从不表示无限。单次调用参数0关闭该轮。副本/未知 `pushRole` 不采集，推送调试用 `QD_PUSH_FORCE` 不解除这个限制。

预算、轮转位置和逐code退避固定保存于 `V6_BO/data/history-backfill-private/budget.json`，HTTP请求不能指定路径。网络前先持久预留整轮预算并给各code设置15分钟恢复等待；重启不能退还已预留预算。落盘/内容校验失败停止回填，不能退回无账本采集。旧部署没有此前用量证据时明确记 `prior-usage-unknown` 并等待15分钟冷启动，只允许随后有界额度；这不能证明升级前当日累计请求数。目录必须放在持久卷；若整卷丢失，缺失账本仍只有保守冷启动证据，不能宣称已知此前用量。

源无数据、日期落后、断线等按code等待15/30/60/120/240分钟，最高6小时。队列轮转可继续处理其他票，避免同一首批卡住全市场。预算使用中国日历日期跨日重置，退避跨午夜继续；时钟倒退不能重置预算。目标日为中国最近15:30已结束的交易日，跨周末/节假日回退；不会用周一凌晨去追当天尚未出现的日线。

短历史只有有有效新上市日期、末行已到目标日且不足6根时，等下个交易日15:30再补；其他短历史不会被猜成完整或新上市，继续有界退避。只有明确 `historyComplete:true` 的供应商元数据才允许对旧股票短历史暂停7日。现有公开适配器不提供该完整性字段，因此不能声称供应商已认证完整历史。

新鲜度同时检查供应商末行日期和缓存写入时点。旧返回不重写缓存、不改报价/接收时点或来源；新缓存保留供应商字段。无新增不重跑学习入库。预算状态统计的“预留尝试”包含进程中断前尚未完成的代码，这是保守计数。整批执行跨中国午夜时，未发出的代码停止，避免把昨日额度带到次日继续请求；已在途单票的供应商回退仍属于共享HTTP访问控制范围。

本修复仅收口历史维护。旧主页 `/api/refresh` 和其他采集器的共享缓存/访问控制由其他变更处理；没有修改锁定的 `public/index.html` 或 `public/mobile.html`。**唯一primary采集进程是硬性部署前提，不可并行滚动启动两个primary。** 本账本不是跨进程分布式锁：两个primary即使用同一文件，也可能各持旧状态；若使用独立数据卷则更各有自己的额度。没有验证生产部署是否满足此前提。
