# 2026-11-09：行情原始时点、周末新闻与飞书现场验收清单

## 这批源码实际改了什么
- 每日与周末新闻定时器改用独立的北京时间日历视图（`src/core/news-china-clock.js`），不再依赖工作机/云容器的 UTC、日本或美国本地时区。周日 21:00–23:59（北京时间）走周末汇总，其他日 21:00–23:59 走每日汇总。周六/周日日期标签来自同一北京时间时钟。
- 调用既有 `isTradeDay` 的新闻标题判断也用北京时间视图；**没有修改**原四套策略、成交/结算、持仓风控、交易日门禁、推送通道与账户账本。
- GitHub 的手动公开行情诊断现在对**同一次**有限采样做读取时的时点投影，按来源展示 `原始报价时点`、`距检查时刻秒数`、`dated-snapshot/unavailable/fresh-unverified`。不再把 HTTP 200 当成真实实时行情，不重抓第二轮、不输出价钱及私密信息。

## 如何运行一次免费行情诊断
打开 GitHub → Actions → `V6 public quote diagnostic (manual)` → Run workflow，输入六位沪深代码（例：600519）。输出在本次 Actions Summary 和作业日志中；该工作流是手动一次性诊断，不自动监控、不调用付费接口、不启动实盘交易。已设计为最多三路公开来源，遇 403/429 不绕过；**是否允许商业使用**仍以官方许可为准。
- 同一条来源出现 `dated-snapshot`：保持原始时间，不能说本轮实时已接通。
- `fresh-unverified`：仅距上游自报时间不超过 15 秒，不代表交易所认证或可成交性。
- `unavailable`：拒绝用其他来源的时间替换失败来源，不造最新报价。
- 三路指标只说明一次外网结果，不能代表中国大陆长期稳定性；如需时段稳定率，需要授权环境的连续监测和限频凭据。

## 飞书和周末必须的现场验证（尚未完成）
1. 在唯一云端主实例确认新闻/公告来源已授权且确实在周末拉到带发布时间的新闻；盘面显示上个交易日，不因网页刷新产生新策略信号、模拟成交或重复采集。
2. 在北京时间周六/周日，用隔离或由用户控制的**私密机器人**核实一次手动准许的消息。检查消息能在手机真正收到、内容时间是新闻发布时间且不包含私人持仓或密码。公共群不能用作私密通道失败后的退路。
3. 云端发送日志须能区分 `gateway-accepted`、`pending-unknown`、`gateway-rejected` 与设备实际到达（后者需用户终端确认）；未知回执不要盲目重发，跨重启去重状态需保存在有备份的持久化卷。
4. 让手机、电脑分别单独在线并交叉刷新，检查同一个云端观察池/新闻快照版本，关闭另一端不影响当前读取；检查 iPhone Safari 和电脑实际渲染，逐图对照用户参考原图。当前测试只有浏览器隔离页面几何验收，非原图逐像素、非正式外网真机。
