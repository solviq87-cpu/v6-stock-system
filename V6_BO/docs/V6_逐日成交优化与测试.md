# 逐日交易状态与回测成交优化
## 对照审计
统一主线手机卡片版和模型并行版的买卖执行都使用逐日盯市账本。沿用其 T+1、受阻续持和次日执行的设计。本次在模型并行版修复成交边界与状态传递。UI、鉴权、安全及部署仍由主线维护。

| 原版复现 | 本批行为 |
|---|---|
| 开盘 10.99，买入滑点 1%，计算为 11.0999，超过输入的当日上限 11；开盘 9.01 时卖出价亦可能低于下限 9 | 未触限开盘的模拟滑点限定于相应日限价，示例买价 11、卖价 9。开盘已触限仍按原有保守规则阻断。 |
| 显式不可交易的卖出日仍能成交 | 保留持仓、逐日估值，恢复交易后重试 |
| 信号日逐日标志与执行日默认状态不一致时可能误买 | 使用执行日风险标志，字段缺失沿用提供的标的级假设 |
| 重复候选先占满排序名额，漏掉另一个标的 | 按顺序去重后分配组合名额 |
| 缓存规范化丢弃每日限价、ST 和停牌等状态 | 校验并保留逐日字段，扫描按当日风险过滤 |

## 输入与限制
逐日数据可附 upperLimit、lowerLimit、limitPct（正数）、isST、suspended、tradable（布尔值）。缓存适配器发现字段类型或限价顺序矛盾则返回错误。逐日价格界限优先于估算比例。源数据未提供时，静态状态和估算比例仍是模型假设。限价内成交并不证明盘口有足够的流动性；没有新增盘口、撮合队列或真实数据源。
