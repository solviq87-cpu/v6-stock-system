# V6 选股单页：日/月/年K历史翻页修复（2026-11-09）

## 问题与原因
- 选股内页一次请求 `/api/kline?code=...&n=1200`，但原服务端仍将 `n` 限制为最多 240 根，因此年线通常只有不足一年多数据。
- 老接口升序历史日线的 `end` 查询用了第一根**早于**指定日期的记录作为切片终点，常会取到索引0并返回空结果；不是服务器不支持更早历史，而是翻页边界算错。
- 生产真实源能否提供几年历史仍由 `klineRows` 决定；**不制造不存在的日线，也不伪称已经解决授权数据覆盖**。

## 修复
1. `src/core/kline-read-pagination.js`：纯函数；先验证所有历史日期按日严格递增，再按 `end=YYYYMMDD` **排除该日及以后日期**，单次最多240根、附上 `hasMore` 和下一页 `nextEnd`。日期无效、重复、逆序拒绝。
2. `server.js`：原 `GET /api/kline` 授权、取数、调用时序不变，改用上述时间边界；到数据最早端返回 `rows:[]` 与 `hasMore:false`，而非数组越界异常。未增外部 API / 并发采集。
3. `public/assets/picks-three-k.js`：打开股票日K只读取最新240根；用户点月K或年K时按需补读较早历史，最多6页，不重复读取边界日。同一代码分页复用已取得的数据；切股、权限撤销取消旧请求并隔离迟到响应。服务器只有短历史时保留“数据不足”而不造历史。
4. **两份原主页字节不动**；只更改现有 `/picks.html` 的 JS 及受保护历史路由，不创建新首页入口；不用动四套正式策略、权重、模拟账户、飞书推送。

2. **同家族战法合并**：突破+放量的相关策略只算一类独立证据，避免3条相似条件冒充3套预测优势。
