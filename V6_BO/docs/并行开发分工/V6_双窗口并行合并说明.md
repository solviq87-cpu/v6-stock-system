# V6 两个聊天窗口的共同工作约定

1. **共同祖先**：两边必须从同一个 `V6_Latest_Full_Project_Batch_Evidence_Isolation_20261104.zip` 开始，不是分别从自己记得的“最新版本”开始。
2. **任务分工**：当前窗口负责 A01–A05、B01–B05、F01、F02；新窗口负责 C01–C04、D01–D04、E01–E04。24 项固定编号，不新增互相冲突的编号。
3. **原条件保护**：保留五大策略族、14 条原规则、阈值、权重和历史文件。修改必须逐条列出旧值、新值、原因、测试，并经用户明确认可。
4. **禁止整包覆盖**：两个窗口各自输出完整 ZIP，但最终由 A 窗口按共同祖先做三方文件级合并；冲突逐项审查，尤其是 `server.js`、`strategy-service.js`、`public`、`docs` 和测试。
5. **接口约定**：新行情/评分接口由 B 窗口提供 JSON 契约与示例；A 窗口按契约实现 UI 与权限；不互相篡改核心算法。
6. **真实验收**：隔离单测、真实 HTTP、浏览器/手机、真实行情、短信服务商、云端部署分开记录，不混淆。
7. **每批交付**：完整 ZIP + 差异清单 + 测试命令及原始输出 + 未完成项 + SHA-256 + 恢复检查点。用户数据及凭证不得写入公开报告。
8. **最终合并**：需要用户把新窗口最终 ZIP 发回当前窗口；聊天窗口之间不会自动同步源码或改动。
