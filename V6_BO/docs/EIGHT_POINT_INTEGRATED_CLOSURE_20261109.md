# V6 八项整体联动 · 单批次验收说明（2026-11-09）

> 用户要求：不要把八项拆成八个互不相干的项目；统一做成同一个入口、同一份证据、同一轮回归。当前本文件记录**整合到代码链路**与**真正现场验收**两层，绝不混同。

## 唯一入口和现有资产
- 既有编辑权限接口 `POST /api/research/complete-run` 和研究页保持不变，返回结果中追加 `eightPointFlow`。服务器上的原研究验证、四套正式策略、权威模拟账户、交易风控和回测调用顺序保留，统合结果仅**读取既有计算输出**。
- 可在本机用 `npm run research:eight -- <本地JSON>` 一次获取八项证据摘要（Node.js 22；所有输入放本机，不上传仓库，不传私密持仓或密钥）。
- `public/assets/complete-workbench.js` 在电脑和手机响应式研究页展示八个可展开模块。所有用户可见内容均使用 `textContent`，避免将公告/公司名称拼进原始HTML；仍需真机点按和参考截图视觉验收。
- 每次研究记录八个固定 `id` 的结果与待办；`codeConnected=8` 仅表示汇总模块全部运行，不代表八项业务“已完成”。所有 `externallyAccepted=false`，`productionReleaseReady=false`、`canTrade=false`，实际权重不变。

## 同一轮研究的八项
| 项 | 当前整合的真实模块 | 仍未通过的外部/现场验收 |
|---|---|---|
| 1 大盘 | `historicalExplanations` 的同日指数/广度与 `market-sector-resilience`；必须声明数据来源，不能借日期补实时 | 国内合法来源、交易所指数/广度实际核验与盘中源时效 |
| 2 板块 | 相对指数强弱、可比样本内RPS、弱市银行保险券商白酒研究降序 | 完整板块映射、成分覆盖与资金流合法性、指数同日对账 |
| 3 个股联动 | 原策略命中→研究观察 `signal-pool-lifecycle`（单次运行）→独立板块/大盘解释 | 用户跨日自动观察池的**可信持久化**、真实盯盘 |
| 4 入选解释 | 每票规则ID/条件证据、为何选中、为何上涨的同期证据、风险；单独标记没有认证因果 | 公告原文、企业事件影响、历史K线正确性核对及真实UI |
| 5 风控 | 原权威账本与回测的双账核对、历史数据质量检查、已知风险；现有本机私有手动持仓只读HTTP接口指引 | 本机数据接入、推送真实送达及撤权、真实风控拒单与额度 |
| 6 学习规则 | 冻结规则5日净收益人工升降权复核和同股重复信号去重；完全不写权重 | 独立样本、统计显著性、市场多阶段、公司行为复核和人工批准 |
| 7 公开策略分层 | 原四套正式策略入口稳定；已有公开/联动/质量研究战法目录和命中，研究层与正式策略分离 | 各规则实际授权、历史多窗口、人工晋级，不允许研究命中越权 |
| 8 自动测试 | 八项集成模块、客户端渲染、完整后端/网页回归、账户核对和安全边界，GitHub CI分别记录 | 实际供应商网络、生产HTTPS部署、真机及真实推送送达另验收 |

## 关键禁令
1. 不允许从旧705或733版覆盖 `dev`。不修改原四套正式策略、15因子权重、原模拟盘权威资金和订单处理。
2. 研究观察池只记录具有有效历史输入和研究资格的票；**同一次运行并不是跨日自动跟踪持久化**。缺数显示未知；不得把历史的“近期”当作当前的15秒实时行情。
3. 大盘/板块/涨幅是同时观察到的历史相关现象，不推断上涨原因，未经核验的公司公告仅为待核对线索。
4. 新增战法的升降权只作为**人工复核顺序**，没有具体权重修改指令。亏损、停牌、涨跌停、公司行为未知、弱市数据全部保留。
5. 本机手动持仓风险资料与双源报价冲突检查保留在独立私人文件和本机鉴权接口。八项报告不会从账户文件读取或上传私密股票仓位，也不会自动发送短信/微信、飞书。
6. 本文件不证明供应商授权、实时行情、策略盈利、生产发布、HTTPS证书或手机/电脑1:1视觉。

## 一次测试，八项都检查
本地：
```bash
cd V6_BO
node --test tests/eight-point-flow.test.js tests/research-explanation-ui.test.js
npm run check
npm test
```
独立CI的 `verify` 和 `verify-web` 两项必须同时绿灯，并另查合并后 `dev` 的结果。CI和GitHub步骤摘要仅确认被执行的自动任务；外部证据不能在离线测试中伪造。

## 阻塞项及验收所需输入
- **真实行情**：供应商合法许可、境内网络与服务器实际时点/频控/熔断日志；未授权前只能离线研究和隔离的历史导入。
- **提醒送达**：用户指定的私有通知渠道、凭据和接收设备，验证签收、误报与撤权；此前只是本机可见风险。
- **观察池持久化**：安全备份、账户权限、重复执行幂等、跨日期真实来源和故障恢复核验。
- **部署和视觉**：目标服务器/域名/HTTPS/持久化/回滚、电脑与iPhone实际截图及按键验证；在具备权限和环境以前保留为未验收。

每轮使用GitHub PR+CI+合并后检查，并把证据写回 [八主线总账 #23](https://github.com/solviq87-cpu/v6-stock-system/issues/23)。该账本必须区分“代码接入”“自动测试”“真实上线”，不能把任何一栏自动标成全部完成。
