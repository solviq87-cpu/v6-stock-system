# V6 影子因子自动学习：私有档案备份/恢复前只读对账（2026-11-10）

## 解决的问题

V6 研究 Worker 已支持不可变的 `shadow-*.json` 研究模型与已消耗保留集试验，以及 `prereg-*.json` 事前候选注册。但旧备份若**缺失一次失败/拒绝的研究试验**，或缺失事前候选登记，就有机会在恢复后遗忘已查看的样本外数据。单份报告 SHA256 完整不等于**全部历史报告齐全**。

本阶段增加一个**仅只读**的研究私有目录对账 CLI，并不构建备份、复制文件、删除旧归档、重置预算、运行自动学习或恢复任何工作目录。

## 使用

先人工停止并核实所有研究写入器，确保原始和候选目录均已静止、没有 `.shadow-worker.lock`，然后：

```sh
cd V6_BO
# 验证一份新备份：第一参数必须是可信、当前完整的原始研究目录
npm run factor:shadow:archive:audit -- /绝对路径/可信当前研究目录 /绝对路径/待备份研究目录

# 恢复前核验：第一参数必须是独立保存的最新可信完整备份或可信清单对应目录
npm run factor:shadow:archive:audit -- /绝对路径/独立可信参考目录 /绝对路径/准备恢复的目录

# 直接使用 Node 入口亦可，作用完全相同
node scripts/factor-shadow-archive-audit.js compare /绝对路径/参考目录 /绝对路径/待核验目录
```

成功只输出聚合摘要 `ok:true`、`status:shadow-archive-preserved`、总文件数、研究报告/预注册文件数、按不可变**原始字节**计算的目录摘要等，并明确 `readonly:true`、`canTrade:false`。**成功不执行实际恢复，也不自动继续研究。**

## 对账协议

1. 研究目录均必须为私有绝对路径、真实目录；拒绝 `public` 路径、符号链接和写入独占锁。研究目录的**不可变证据**只接受严格文件名模式的 `shadow-YYYY-MM-DD-<fp12>.json` 和 `prereg-<fp12>.json`。当前 dev 还按严格模式核对 `prereg-<fp12>.json` 中的 seed 模式不可变预注册种子，旧草稿未含此项；以现有归档校验器为准。另外允许 PR #165 值守监控使用的**可变运行状态** `.shadow-worker-heartbeat.json`：必须验证它的普通文件类型、完整字段与本地 SHA256，但不将它计入历史备份清单/研究模型数，也不要求两份备份心跳原字节一致；它**不证明模型训练已完成**。如果目录只有心跳而没有一份不可变模型或注册档案，仍拒绝；其他未知/残留临时文件、符号链接、写入锁及超出审计上限一律拒绝。
2. 逐份解析 JSON，校验封存字段、`fingerprint` 对完整负载的 SHA256、不可交易声明，以及文件名中指纹/训练截止日与报告一致。已消费试验的 `trialAudit` 状态与报告状态必须一致；旧无该字段报告仍保留其原始字节。
3. 对可信参考目录的**全部**不可变文件（包括失败试验和任何预注册候选），在待检查目录逐一核对**文件名与原始字节SHA256**。少一份或重写/重新排版同名文件都拒绝。目标目录可包含额外的合法封存文件；这些新增文件**只是格式完整，仍需独立审查其来源**。
4. 在对账结束前重新扫描双方目录摘要，若期间发生变化则拒绝。不是跨主机原子快照协议，不能代替停写、只读快照和异地独立备份。
5. 本工具**不能证明参考目录本来就完整**。若参考目录本身已丢失记录，任何本地 SHA 都不能凭空恢复缺档证据；必须使用独立保管的最新可信快照、文件清单或外部时间证明。不能拿待恢复目录作为其自身参考，也不能靠换新空目录绕过预算。

## 验证和回滚

```sh
cd V6_BO
node --check scripts/factor-shadow-archive-audit.js
node --test tests/factor-shadow-archive-audit.test.js
npm run check
npm test
```

离线合成专项用例覆盖：真实 byte-for-byte 复制通过，丢弃失败试验或预注册失败，同名重写即使内容指纹有效仍失败，重新签名却换了文件名失败，改动负载、未知文件、符号链接、残留锁与空目录拒绝，可信新增档案可并存；不同合法心跳时间戳不影响历史完整性比较、伪造心跳或只剩心跳均拒绝。CI 全量通过只能证明静态测试，不等于**云端实际研究卷**已备份、数据授权已核对或历史盈利性能得到验证。

该研究归档对账与现有账户灾备脚本 `secure-backup.js` 是独立用途，绝不能把此命令冒充资金账户加密备份/恢复。
