# V6 飞书双通道统一推送约定（2026-11-05）

本工程已沿用原 `pushAll` / `feishuProbe` / 串行限频队列，默认私密；仅明确 `public:true` 可进入公共通道。私密失败、超时或结果未知均不得转发到公共机器人，即使 `mustDeliver:true`。

## 配置（不将真实 Webhook 打包）

优先读取以下环境变量，未提供时兼容原 `config.json` 中的设置：

- `V6_FEISHU_PRIVATE_WEBHOOK`：本人私密机器人地址（选股、持仓、风险、验证码、设备授权）。
- `V6_FEISHU_PUBLIC_WEBHOOK`：公共群机器人地址（仅显式公开信息）。
- `V6_FEISHU_PRIVATE_SECRET`：私密机器人签名密钥（如启用签名）。

已有两个飞书机器人仍按**私密/公共的原有角色**使用；由于此前地址已在聊天中公开，应先在飞书重置 Webhook 后填写新地址。真实地址和密钥不要放入源码、ZIP、截图或日志。

## 行为及边界

- `pushAll(text, false, {private:true})` 或省略 opts：私密通道。
- `pushAll(text, false, {public:true})`：明确授权的公共市场信息。
- 验证码只经私密机器人，不通过真实短信；私密通道不可用时返回未送达，不允许公共兜底。
- 复制/测试环境禁止真实发送；结果未知不盲目重试，避免重复推送。
- 更换通道走开发者授权的 `/api/config`，建议 `verify:true` 先体检后切换。环境变量覆盖配置时，需要修改部署环境变量才能切换生效地址。
- 请勿将开发者密码、观看密码、重置令牌或验证码写入推送日志。

## 验收状态

本批仅完成通道配置的安全接线与约定固化；真实飞书机器人发送、回执、限频、跨设备密码找回仍需在用户部署环境验证。
