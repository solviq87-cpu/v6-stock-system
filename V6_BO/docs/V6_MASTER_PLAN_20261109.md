# V6 智能选股系统 · 全任务路线与验收大纲（2026-11-09）

> 基线：`solviq87-cpu/v6-stock-system` 的 `dev` 分支。旧本地746项历史通过结果仅作追溯，**不是当前CI结果**；每次改动以新提交及对应CI记录为准。不从旧705/733版本覆盖。不得连接真实券商账户或资金。

## A. 八大主线（均为用户确认事项）

### 1. 原策略守护 + 新战法持续纳入
- 永久保留原四套体系、现有K线形态、15个扩展因子和既有风控逻辑。
- 持续审阅有许可的GitHub/公开文档与学术来源；只学习规则设计，独立编程，不复制受限代码。候选规则必须可运行、可显示每个条件、可逐股命中，不得只在UI中堆名称。
- 目前已开发研究层：原10个研究战法和2条公开技术组合（PR #9）；PR #14 已合并新增“唐奇安20日突破、窄幅蓄势放量、大盘板块个股相对动量”及5项逐股因子（见 `LINKED_PUBLIC_FACTORS_20261109.md`）；新增三战法的可选时间隔离前瞻验证见 `LINKED_RULE_FORWARD_AUDIT_20261109.md`，仍需CI和成本/数据真实性验收。
- 研究池：任一**完整且证据有效**的战法命中可申请观察；多战法只按独立策略家族增加观察优先级，不能把高度相关的两个技术变形当成双重独立证据。正式候选资格不因研究命中而绕过风险门禁。

### 2. 大盘—板块—个股三级联动
- 大盘：上证、深证、创业板及可选A50；涨跌家数、成交活跃度、涨跌停、超跌/暴跌环境；日期、数据源和时效要核对。
- 板块：行业/题材涨跌、相对强度、成交额及可信资金流、龙头与宽度；大盘下跌时找逆势、抗跌板块而不是一律屏蔽。
- 个股：技术条件、相对动量、量价、所属板块位置、公告、基本面与风险；识别银行、保险、券商、白酒等避险/权重板块，在市场弱时按用户偏好进行有解释的研究过滤。避免不加判断地推荐权重股。
- 缺实时或跨来源数据标为未知；不能根据一个网页展示的当天请求时间伪造逐股报价日期。

### 3. 大跌阶段学习保护
- 突发系统性急跌不得仅凭短期盈亏自动降权/淘汰因子；仍保留所有暴跌样本、亏损、风控与回撤。
- PR #6只读诊断、PR #12新冻结学习方案的真实参数晋级门禁已经合并；其他学习通道尚需逐个接入和审查。
- “不可抗力”仅凭跌幅不能自动断言；需要外部可核实事件和时点证据。

### 4. 个股入选与上涨原因解释
- 每只入池股票必须展示命中战法、条件值、K线、15个因子、来源时间、大盘和板块是否共振、公告原文线索、风险、持仓或观察状态变化。
- 单独回答“为什么入选”与“为什么上涨”。后者仅可解释客观上涨幅度、同期板块表现及核实事件；未确认直接驱动时写“可能相关/无法判断”，不能声称有已核实因果。
- 已有后端理由引擎与综合研究页面；主仪表盘、参考图详情交互需端到端验收。

### 5. 模块间真联动
`合法行情/公告 → 来源质量与交易日历 → 大盘状态 → 板块分类 → 原策略/新规则 → 风控 → 观察池自动流转 → 个股解释 → 模拟盘与持仓提醒 → 历史跟踪与回测 → 学习保护/审计`。
- 同一股票不同信号可独立追踪；成熟结果要分组展示。未更新数据不按零分处理。
- 对互相冲突的技术、公告、市场及风险信号要单独显示，风控优先。

### 6. 行情来源、国内访问和数据真实性
- 优先有明确使用权限、免费/低成本的境内可用行情与公告；按数据许可、频率限制和接入稳定性验收，遵守官方或公开接口限制，不接高价付费接口作为强制依赖。
- 东财/腾讯公开接口及时间校验已有代码；PR #13修复逐股报价原时间与请求时间混淆。外部独立认证、国内网络实测、退化/熔断记录、真实持续采样仍未全面完成。
- 行情时效、源、模式（导入/历史/模拟/公开网页）必须显式显示；无数据时不能冒充实时。账户/隐私不得暴露到公开编辑器。

### 7. 模拟盘、盯盘、风控和学习回测
- 原模拟盘结算、成交费用、T+1、涨跌停、行业/策略集中度、连续亏损、撤销与审计均保留；不接真实账户、真实资金或真实自动委托。
- 用户可提供证券代码/持仓成本/仓位，以合法数据源监控、提示风险；实际提醒渠道、数据时效、风险阈值需端到端测试。
- 新策略须做1/5/20/60个交易日未来跟踪、样本外、费用/滑点、停牌、ST、除权、重复信号相关性和可成交性校验。研究规则未经验证不得自动更改原四套正式参数。

### 8. UI、CI、GitHub同步与自动发布闭环
- 电脑/手机响应式界面尽量按用户参考截图 **1:1** 还原，包括信息层级、交互、策略入口、K线、个股理由、观察池、市场/板块图和风险展示；没有视觉对比与实际验收不能声称已还原。
- 改动经GitHub分支→自动后端和网页全量测试→修复→合并 `dev`；操作历史、验收状态和回滚方案持久记录。用户已允许正常安全范围内无需每次重复口头确认。
- 自动部署到 Workbuddy 或未来国内平台的前提是可持续的发布连接/凭据与最小权限配置，需明确前后端能力、持久化限制及HTTPS、跨端访问。**GitHub CI通过≠Workbuddy更新/国内上线成功。**
- 公开共享编辑器对持有链接的人可能有写权限；不可放真实密钥、账户/资金数据和私人仓库完整源码。

## B. 工作包与验收顺序（状态以 GitHub 最新提交和CI为准）
- **P0 守护门禁**：冻结原策略/资金/数据协议、差异检查、完整CI和回滚；完成一次发布前强制复验。
- **P1 开源研究扩充**：按“来源核对→公式实现→逐条命中→独立族去重→证据展示→成本回测→可选晋级”推进。本批新增3战法/5因子；后续可评估：板块RPS、成交额持续性、波动收缩、多周期强弱、量价背离、资金持久性、市场情绪、竞价承接、公告风险、龙头带动、北向统计可用性（数据缺失不造假）。
- **P2 同日三层联动**：对接可信指数与行业序列，核对交易日，断言来源时效；新增同板块横向比较与逆势/超跌逻辑。
- **P3 个股解释与观察池**：每股必须有入选条件、利多/风险、为何上涨的证据等级及后续跟踪结果；策略点击显示真实命中股票。
- **P4 研究与学习验证**：为每条新战法补分策略的样本外与市场环境切片、交易费用/可成交审计、独立信号去重。
- **P5 真实行情端到端**：实际部署环境检查免费公开接口HTTP状态、限频、时间戳与备用源，收盘后和交易时段区分；输出未连接、不可用与过期状态。
- **P6 模拟盘、持仓盯盘、提醒**：模拟账户、持仓风险、行业集中度与公告预警端到端打通；通知到达率和误报追踪。
- **P7 视觉还原与国内发布**：基于用户参考截图做逐项1:1对照与移动端测试；自动部署流水线、回滚、数据持久化与国内访问验证。

## C. 验收定义
“代码提交”与“CI通过”分别记录；“实际行情接通”需有真实HTTP与时点日志；“前端可用”需真实点击/屏幕验证；“线上部署完成”需目标域名返回对应构建版本、真实数据和权限测试；“策略有效”需独立回测及样本外置信依据。未知、待确认和失败状态允许并必须如实展示。
