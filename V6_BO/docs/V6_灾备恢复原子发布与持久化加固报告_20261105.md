# V6 灾备恢复原子发布与持久化加固报告

## 本轮范围

本轮只修改灾备脚本 `scripts/disaster-recovery.js` 及其专项测试，不修改 UI，不接入模型网关，不产生云资源费用。

## 修改内容

1. 原子写入在发布前对临时文件执行 `fsync`，重命名后同步父目录，提升断电/进程异常时的持久化保障。
2. 恢复流程先在目标目录同级创建权限为 `0700` 的暂存目录。
3. 所有备份文件写入暂存目录后核对文件清单，再将完整目录一次性重命名发布，避免恢复过程中目标目录暴露为半成品。
4. 允许将数据恢复到已存在但为空的目标目录；非空目录、符号链接仍拒绝。
5. 备份清单增加规范 ISO 时间戳校验，拒绝非法日期和非规范时间字符串。
6. 失败时清理暂存目录，不覆盖已有非空数据。

## 测试结果

- 灾备专项：10/10 通过。
- 全工程 Node 测试：`node --test tests/*.test.js`，390/390 通过，失败0、跳过0。

- 本结果仅代表当前工程内自动化测试；不代表真实云端断电、磁盘故障或生产环境恢复演练已完成。

## 未完成边界

- 尚未执行真实 ECS 环境的磁盘故障与断电恢复演练。
