## 合并及兼容
1. 优先合入 src/strategy 的代码、工具和测试，再合并大纲新增段落。恢复检查点记录本分支哈希，主线须保留双方历史，基于最终文件重新生成校验值。不要用本 ZIP 覆盖已前进的主线目录。
2. 已有扫描/回测 HTTP 路由和权限入口保持原签名。旧 walkForward 的 end 仍表示最后信号日，原周期 equity 保留，另有 dailyEquity、在途持仓与订单。卖出受阻时保留未实现损益；收益统计、成交数量可能变化。该兼容入口用整数股、无独立卖出税，主研究入口 ledger 默认整手并计入卖出税。
3. 回测信号仅接收截断 K 线。动态分数从对应 bars[i].factors 读取，必须是该日收盘时已公开的值。股票顶层策略分数不再回填历史。静态 isST/suspended/tradable 声明在缺少逐日状态时作为全样本假设；实际状态变化必须按日传入。自定义 selectCandidates 仅供可控实验，调用者不得在闭包引用未来数据。
4. ledgerBacktest 新增可选 stopLossPct、maxPositionPct、drawdownAlertPct，单位为百分数。止损以收盘价对比模拟买价，最早下个交易日出场；受阻继续持仓。仓位上限针对新开仓预算，不强制再平衡。每次跨过回撤阈值记录预警。可提供 tradingDates（以 bars[0] 对应日期起始的完整交易日数组）；缺失交易日要先显式补停牌行，无日期仅限已对齐的研究序列。
5. bars[i].upperLimit/lowerLimit 可提供未复权逐日限价；否则沿用板块比例估算。开盘触及相应边界保守拒绝；不因盘中开板假设开盘成交。日成交量仅作无交易日的过滤，不提供盘口流动性和排队信息。开盘加减固定滑点仍是近似成交模型。仅凭日线无法认证交易所涨停或实盘可成交。
6. node tools/research-runner.js holdout 输入.json 使用 stocks、start、splitDay、end 和 ledger 参数。训练区间为 [start, splitDay-1]，评估区间为 [splitDay, end]；分别从相同初始现金开始。最小可用示例为 50 日数据、start=27、splitDay=35、end=49。必须在查看样本外结果之前冻结因子、参数、股票池和分割点。
7. refreshHistorical 保留原调用方式。retries 为每源附加尝试次数（0–2，默认0），超时不在同源重试；authorizedFallbacks 最多两项，须提供 name、authorized:true 和 fetchKline(code, count, {signal})。primary 必须由调用方选择；已有 em.fetchKline 内含供应商切换。若需严格供应商白名单，主线应传单一主源和确有许可的回退适配器；authorized 标识代表调用方声明，不能验证许可。总延时可随尝试次数增长，不响应取消的上游工作可能继续。没有附加授权凭证或新公共 HTTP 入口。
8. 战法增加 risk、riskLevel 和 riskBlocked；硬过滤后的状态为 risk_blocked，属于研究提示。首板质量规则识别已形成首板，不能视为盘前发掘能力。低吸本批验证趋势缩量回踩这一子类。真实因子口径、风险分级及策略有效性尚未用授权历史数据校准。
