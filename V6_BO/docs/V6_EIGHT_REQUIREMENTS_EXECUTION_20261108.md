# V6 八项闭环需求执行合同（2026-11-08）

## 统一验收目标
按用户确认的八项要求持续迭代：保留四套原有选股规则和既有功能；公开仓库和网页策略经来源及许可核对后作为独立研究候选加入；建立上证、深证、创业板、A50与板块、个股三级联动；市场系统性急跌不得直接推断因子失效；个股需要解释入选理由与上涨的可核实依据；行情→市场→板块→策略→风控→池子→解释→预警→回测形成闭环；优先合法可用数据，杜绝假行情；桌面和手机界面、自动测试和可恢复部署保持一致。

## 规则优先级
1. 原有策略阈值、历史信号、账户账本、模拟盘成交规则、数据供应商认证和通知权限不得静默修改；研究插件与正式规则隔离。
2. 任一完整战法通过可进入研究观察，多战法共振可提高观察优先级；模拟数据、证据缺失、停牌及涨跌停风险不得包装成可成交推荐。相关信号不重复计算为多份独立证据。
3. 大盘环境包含三个境内指数和可选A50；板块相对强度、宽度、资金变化与龙头验证需与个股同一交易日和有效时点。市场和板块证据不足时输出未知，不能取零冒充弱势。
4. 个股解释须包含原生或新增策略命中条件、行情时点、板块与市场联动、个股量价、公司公告或资金证据、风险冲突、观察状态及跟踪变化。对为什么上涨，已证实事实与可能解释必须区分，未知明确标未知，不能编造因果。
5. 异常市场阶段暂停仅凭短期表现自动判定因子失效或参数晋级；亏损、最大回撤、成本、风险预警和模拟交易熔断仍照常记录。不可抗力必须有可靠事件证据，不能靠跌幅自动认定。
6. 新策略从可信公开来源提取规则与出处，独立实现且遵守许可；A股T+1、停牌、涨跌停、除权、流动性、费用、滑点、次日开盘执行和样本外验证未满足时禁止进入正式交易逻辑。
7. 免费公开数据、收费数据、离线历史和合成测试数据必须明确分层标识；缺价、无时间戳、来源过期、跨股票证据不得伪装成实时值。
8. 每次改动执行开发分支推送→CI自动测试（后端+网页构建/测试+服务启动检查）→修复失败→审查合并；已经授权的仓库代码更新无需反复向用户索取口头确认。GitHub 上传和 CI 不等于线上部署；任何自动发布需要平台连接、密钥及独立部署门禁，严禁泄露配置和账户数据。

## 本批实现及范围
- src/core/market-shock-learning-gate.js 是只读研究诊断门禁；预设研究阈值：境内三大指数中至少两项当日跌幅不高于-3%，股票上涨比例不超过25%，市场覆盖率不低于80%，观测发生于评估时点之前、同日且90分钟内。阈值未经历史校准。
- src/core/factor-health.js 的 evaluateFactorHealth(...,{marketContext}) 可选注入该门禁；没有输入时旧报告结构及评分保持不变。learningGate.deferLearningUpdate=true 仅表达建议暂缓学习调参，不会自动改动学习注册器、权重、策略状态或风控。
- 来源不完整、未来时间、模拟输入、跨供应商、失效、覆盖不足均标记为 unverified；这不能证明市场正常。横截面评分漂移不能直接证明因子失效。
- 专项测试覆盖跌幅边界、市场宽度、模拟/缺失/未来/过期输入、保留因子告警和不动权重。
- 现有 dev 分支15因子解释、行情真实性校验和双端仪表盘不因本次改动回退。

## 待办：不得虚报完成
- 公开策略中的 Boll+CCI+ATR、ATR+RSI 等仍需独立候选实现及样本外验证，其他研究候选不能称为认证实盘。
- 真正的自动学习晋级需在学习注册器使用冻结市场环境和同类市场样本外比较，设独立回滚门禁；本批只完成只读诊断。
- 用户端三级联动解释卡、个股上涨原因分级、板块信号衰减和手机真实数据需要端到端验收。
- GitHub Actions 当前仅测试，无 Workbuddy 编辑或发布凭据，也未确认新的 HTTPS 预览；CI 通过不代表已部署。
