## 2. 后端全量命中：已做的与尚未做的

- 原 `GET /api/quant-picks` 按代码最多50条，并且历史文档确认它不等于全市场全部战法。**不能将 max=500 当作已解除服务端上限。**
- 新增 `src/core/v6-matches-snapshot.js`，在量化选股**六条件**的完整扫描完成、尚未截断时保存同批次内存快照。
- 新增 `GET /api/v6/matches?limit=100&cursor=...`：按固定快照ID游标读取、核验总量与命中条件数、严格拒绝跨快照混页。该API仅GET，通过原服务门禁，不在分页时触发扫描/模拟成交/推送。
- 前端首选新接口、逐页读取并核对完整性，若无已生成的快照，可调用一次**原有非强制GET**等待初次扫描；仍没有快照时退回旧结果，并醒目标记“只返回部分股票”。
- **重大范围边界：**当前证明覆盖的仅是 `quantPicksScan` 六项条件。四套核心策略及更多新增战法尚未有可靠的统一、不可截断的全量事件存储；不可把本阶段称为“所有战法全部命中”。见 Issue #167。服务重启会丢失内存快照，持久化/冻结与分页一致性下一阶段继续完善。

## 3. 安全约束

- 不接真实券商、不交易真实资金；预览不自动跑模拟成交、不执行发布或启动推送。
- 原凭据 `access.json`、`config.json`、持仓、历史与审计不得纳入仓库或页面请求。
- `QD_CLOUD=1` 时本机回环不免密。新静态HTML在原 `isAsset` 白名单，新数据API仍受 `checkToken` 门禁；`/api/paper` 仅开发者。
- 任何显示都必须尊重原始报价时点、复权/停牌/公司行为、不填充缺损K线，不拿测试值冒充实盘收益。
- 本地旧 V6 现行实例继续运行在已验证的干净Linux副本，更新不得覆盖 Windows 挂载盘存在CRLF疑点的原工作区。
