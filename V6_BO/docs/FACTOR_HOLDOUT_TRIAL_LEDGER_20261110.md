# V6 自动学习第十阶段：失败候选也消耗样本外证据

## 修复问题

第九阶段已能以逐因子反事实判断研究候选是否有害，但旧版调度器只记得**最后一次成功接受**的 `shadow-updated` 模型。因此某次 `shadow-retained` 失败后，下一次研究可重复拿同一批新鲜保留样本换一个候选再试；反复测试最后总有可能偶然出现漂亮指标，这就是适应性样本外过拟合的一条路径。

本阶段给**每次非暂停候选评估（成功或失败）**增加不可覆盖的私有试验账本，绝不直接更改生产因子、四套策略、模拟账户、交易系统、行情接口或两端锁定主页。

## 不可重复消费规则

- 研究模型仍由**训练期**历史冻结因子分数提出影子权重；不改变原有训练/验证/保留集5日 purge、同股持有期去重、分块可靠性、冗余抑制、三版本对照和逐因子反事实判断。
- 每次候选在保留集上进行判断，只看比**上一已接受模型**和**上一候选试验**所消费的保留末日**都严格更晚**的成熟交易日，至少需要5天。即使前一次候选因为验证不合格未晋级，已查看的保留日也不能再当“全新样本外”。
- 一次评估会随研究报告封存 `trialAudit`：`status=consumed`、试验编号、旧试验报告指纹、上一个已接受模型指纹、试验开始/结束保留日、使用的有效日数、候选身份指纹、研究不可交易声明。每轮以 SHA256 对报告完整内容封存且不会覆盖原档案。
- `paused-market-shock`、`paused-shadow-decay`、`paused-shadow-cooldown`、`shadow-recovered` 等未获晋级资格的**监控期**不记为正式候选试验；冷却恢复仍可观察完整警报之后的新10日，但这些观察不会被重用作晋级。对恢复后的晋级，只能再用恢复日期之后的独立新样本。
- 失败的普通 `shadow-retained` 结果只要审过完整新保留集，同样记录为已消费；再次运行旧数据或只新增不足5天，返回 `skipped-no-new-trial-holdout`（不会生成新研究档案）。若存在多个冲突试验占用相同日期/链式指纹不一致，拒绝继续学习。
- 运维明确启动的 `factor-shadow-worker.js` 从**私有不可变影子模型报告**恢复最后一次试验，保留历史链，在重启时仍严格限制重用。对旧版无 `trialAudit` 的 `shadow-retained`，保守视为一次已消费试验并以旧版报告最后观察日期为占用截止。人工删除/重建本地所有档案不能由本地 SHA 自证，需要独立归档备份。

## 验证

```sh
cd V6_BO
node --check src/core/factor-shadow-evolution.js
node --check scripts/factor-shadow-worker.js
node --test tests/factor-shadow-evolution.test.js
npm run check
npm test
```

专项测试覆盖：首次失败也算试验、原样重播不得再用、只新增4日拒绝、累计5个全新日才允许下次试验、失败试验的 `trialNumber` 和 SHA 链、重启后加载同一链、篡改历史报告直接中止。这些用例是**合成研究协议测试**，不是实盘回测收益认证。

## 明确局限

此门禁限制同一研究档案与同一父版本链内重复使用已查看的保留样本，但不具备跨独立机器/人工删除所有归档后的外部防重复证明；如多实例同时在同一私有卷写入，还应使用单主运行锁和完整外部备份。试验次数记录也不自动给出多重假设检验校正后的置信区间。未来可增加全局试验预算、预注册候选冻结时间戳，以及行业/市值中性样本外基准。没有真实授权前瞻样本时，不宣称策略通过真实效果验证。

## 回滚

Git revert 本PR的合并提交，保留历史研究档案。因新版报告多出不可变审计字段，回滚代码时应将其作为只读研究历史保存，不能用旧压缩包覆盖当前工程。
